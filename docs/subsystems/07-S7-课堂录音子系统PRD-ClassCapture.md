# S7 课堂采集子系统 ClassCapture PRD

**版本**：v0.2
**日期**：2026-07-23
**状态**：Phase 1.5-T01 已完成；T02=`PARTIAL`、T03=`PASS`、T04=能力验证 `PARTIAL`（非 Adapter 装配）；G2 正式语义已采用、跨平台验证待独立批准；T05/T06 未启动
**定位**：将课堂录音转换为可复用的纯文本资料，并接入现有 S2 NoteBuilder 管道

---

## 1. Executive Summary

### Problem Statement

课堂讲解包含大量教材之外的重点、例题思路和考试提示，但学生很难在听课的同时完整记录。课后只有录音文件时，人工重听和整理耗时，课堂内容也无法直接进入 AI StudyBuddy 已有的笔记、知识模块和后续学习闭环。

### Proposed Solution

S7 ClassCapture 将课堂录音作为一种资料来源，通过必要的音频预处理和本地 ASR 生成纯文本，再复用 S2 NoteBuilder 已有的资料、标准化文本、笔记生成和知识模块管道：

```text
课堂录音文件
  → 音频预处理
  → 本地 ASR
  → ConverterResult 纯文本
  → S2 normalized_texts
  → S2 结构化笔记 / 思维导图 / 知识模块
```

S7 不复制 S2 的笔记生成能力。S7 的责任在“把课堂现场可靠地变成资料文本”，S2 的责任仍是“把资料文本变成可学习的结构化内容”。

### Success Criteria

- 学生能够把与学期、课程关联的课堂录音作为资料提交。
- 长耗时的预处理和转写采用异步任务，不阻塞前端请求。
- ASR 成功后产出非空纯文本和可审计的非敏感元数据，并进入现有 S2 笔记生成管道。
- ASR 与下游笔记生成的失败状态相互独立；下游失败不得删除已生成的转写文本。
- 默认使用本地离线 ASR，录音、转写全文和笔记正文不进入普通日志、StudyEvent 或家长报告。

## 2. Product Scope

### 2.1 Phase 1.5 MVP

Phase 1.5 的主路径是：

1. 学生选择已有的本地课堂录音文件，并指定现有学期和课程上下文。
2. 后端保存资料事实，异步执行音频预处理与 ASR。
3. ASR Adapter 返回统一的纯文本结果。
4. 转写文本进入 S2 已有的标准化文本和笔记生成阶段。
5. 前端展示当前处理阶段、失败原因及已有的后续操作；笔记可用后沿用 S2 的笔记入口。

MVP 以录音文件上传为主，不要求浏览器持续录音或实时转写。

### 2.2 Complete S7 Direction

总产品定义中的 S7 还包括：

- 视频文件抽取音轨后进入 ASR；
- 课堂手写笔记照片经 OCR 成为资料文本；
- 原始课堂素材在本机留存并可追溯到生成的资料和笔记。

这些方向属于 S7 的后续能力，不代表 T01 已实现，也不得跳过各自的组件、Adapter、API、Worker 和前端门禁。

### 2.3 User Stories

- 作为学生，我希望上传一段课堂录音并继续使用系统，而不是等待转写完成。
- 作为学生，我希望看到录音处于预处理、转写、笔记生成、完成或失败中的哪个阶段。
- 作为学生，我希望转写完成后直接沿用资料笔记页面查看笔记、导图和知识模块。
- 作为学生，我希望 ASR 失败时看到可行动但不泄漏隐私的错误，并可在后续实现支持的范围内重试。
- 作为学生，我希望笔记生成失败时保留已经完成的课堂转写，不必重新执行 ASR。

## 3. Inputs and Outputs

### 3.1 Inputs

Phase 1.5 MVP 的概念输入包括：

- 已存在且有效的学期上下文；
- 已存在且属于该学期的课程上下文；
- 学生主动选择的本地课堂录音文件；
- 原始文件名、媒体类型、大小和必要的音频元数据；
- 后续独立计划确认的本地 ASR 与音频预处理配置。

音频 MIME 白名单、文件大小/时长限制、采样率与声道策略、上传路由和请求 DTO 不在 T01 冻结，由 T03、T05 的独立计划根据 composer 证据确定。

### 3.2 ASR Output

未来 `AuralConverter` 应沿用共同转换层的 `ConverterResult` 方向，至少表达：

- `ok`：本次转换是否成功；
- `sourceType`：课堂音频对应的来源类型；
- `text`：ASR 生成的纯文本；
- `metadata`：不含正文的音频/模型/耗时等可审计信息；
- `warnings`：低质量音频、疑似截断或其他非致命提示；
- `error`：固定、可行动且不回放录音或转写全文的失败摘要。

本 PRD 不修改当前共享类型，也不确定 `sourceType` 的最终字面量；具体类型扩展属于 T04。

### 3.3 S2 Handoff Output

ASR 成功且文本非空后：

1. 后端将纯文本交给 S2 的标准化文本阶段，而不是在 S7 内重新实现笔记生成。
2. S2 按现有规则生成结构化笔记、思维导图和知识模块。
3. S7 页面或状态接口只引用 S2 已生成的资料/笔记结果，不复制正文存储。
4. 若 S2 笔记生成失败，已完成的转写文本继续保留，后续沿用 S2 的重试或人工恢复能力。

## 4. Responsibility Boundaries

| 组件/层 | 未来责任 | 明确不负责 |
| ------- | -------- | ---------- |
| `I:\ai-studybuddy-composer` 试炼场 | 独立验证 SenseVoice/FunASR、FFmpeg、样例格式、CPU 可运行性与输出格式；形成 smoke 证据和能力卡 | 不作为产品运行时依赖；正式代码不得 import 或复制试炼场路径、凭据和临时素材 |
| 音频预处理层 | 按 T03 证据完成必要的格式转换、切片和兼容处理，为 ASR 提供稳定输入 | 不生成笔记，不写业务状态，不决定前端流程 |
| `AuralConverter` | 在 T04 中把音频输入封装为统一 `ConverterResult`，隔离具体 ASR 实现 | 不接收 HTTP 请求，不直接写数据库，不编排 Job，不调用 S2 AI 笔记生成 |
| 后端 API | 在 T05 中校验学期/课程/资料上下文、接收上传、返回统一 `{ success, data, error }` 信封并提供处理状态 | 不在请求生命周期内同步等待长时间 ASR，不向前端暴露文件路径或 Provider 秘密 |
| Job Worker | 在 T05 中异步执行预处理和 ASR，维护有限重试与幂等状态；成功后移交 S2 管道 | 不把全文写入日志，不重复创建下游笔记任务，不承担前端展示逻辑 |
| S2 NoteBuilder | 接收非空标准化文本，继续执行现有笔记、导图和知识模块生成及失败恢复 | 不感知 SenseVoice/FunASR 的具体命令，不负责音频预处理 |
| 前端 | 在 T06 中选择/上传录音、展示阶段状态与固定错误、在笔记可用后提供 S2 跳转 | 不直接读取 SQLite、上传目录、临时文件、ASR 进程或 Provider 配置 |

## 5. Processing and State Principles

### 5.1 Conceptual Stages

S7 的产品状态必须能够区分以下阶段，但 T01 不冻结数据库枚举：

1. 已接收资料；
2. 等待或执行音频预处理；
3. 等待或执行 ASR；
4. 转写文本已生成；
5. 等待或执行 S2 笔记生成；
6. 笔记可用；
7. 某一阶段失败并保留可重试事实。

前端展示可以映射为更少的用户态，但不能把 ASR 失败与 S2 笔记生成失败混为同一种原因。

### 5.2 Retry and Idempotency

- 预处理和 ASR 采用后续计划规定的有限重试，不无限循环。
- 同一任务重试不得生成多份相同的标准化文本或重复下游笔记任务。
- 转写已成功时，下游笔记重试应从现有纯文本继续，不重新执行 ASR。
- 重新上传或明确替换源文件属于新的用户动作，不由 Worker 静默覆盖原始资料事实。

### 5.3 Failure Separation

至少区分：

- 不支持或无法读取的音频格式；
- 音频预处理失败；
- 本地 ASR 不可用、超时或进程失败；
- ASR 成功但文本为空；
- ASR 成功但存在质量警告；
- 转写成功后 S2 笔记生成失败。

所有对外错误使用固定摘要和建议动作，不回放录音片段、转写全文、命令参数、绝对路径或秘密配置。

## 6. Dependencies

### Existing Product Dependencies

- S2 的学期/课程/资料上下文；
- `StorageAdapter` 和统一路径治理；
- 现有资料、标准化文本和 Job 持久化能力；
- S2 Material Worker 与笔记生成服务；
- S2 的笔记、导图、知识模块 API 和前端页面；
- 后端配置服务、统一 API 信封与日志脱敏规范。

### Gated External Components

- SenseVoice / FunASR：T02 composer 能力证据为 `PARTIAL`，只证明候选组件能力，不构成产品选型或装配；
- FFmpeg：T03 的预处理能力证据为 `PASS`，但仍不自动创建 Adapter 或产品运行时依赖；
- G2：已正式采用平台无关的“可验证操作系统级出站隔离”语义。每个实际平台组合仍须独立验证其 OS/容器/虚拟化层的强制隔离；Windows Firewall 只是可接受实现之一；
- 正式产品中的 ASR 调用方式、依赖安装策略与 `AuralConverter`：仍由 T04/T05 的独立计划和批准决定。

composer 或能力验证通过只证明相应组件事实；它们不等于 G2 `PASS`、Adapter 已装配、产品接入或生产发布资格。

## 7. Privacy, Safety, and Local-first Rules

- 默认使用本地离线 ASR，不把课堂录音或转写全文发送给云端 ASR。
- 若未来引入云端 ASR，必须另立产品、隐私和配置门禁，不能由 Adapter 静默切换。
- G2 是对未来本地 ASR 出站隔离证据的门禁：隔离必须由 ASR 进程外部的 OS、容器或虚拟化层强制实施，并具备可审计、可回滚、平台/版本/架构限定的证据。它不把 Windows Firewall 设为产品运行依赖，也不以 `offline`/cache-only、DNS、hosts、代理或人工断网单独视为隔离通过。
- 任一 G2 `PASS` 只对已验证的平台、OS/运行时版本、CPU 架构和隔离实现组合有效；隔离机制不可用时应记录为 `ENVIRONMENT_UNAVAILABLE` 或 `DEFERRED`，不能写成 `PASS`。旧 Windows `G2=BLOCKED` 记录保留为历史事实。
- 原始录音、转写全文和笔记正文属于学生隐私全文，不进入普通日志、StudyEvent、S6 家长报告或连接测试载荷。
- 日志只记录任务 ID、阶段、固定错误码、耗时和非敏感技术摘要；不得把完整 UUID 或正式运行数据写入文档证据。
- 前端不得保存录音正文、转写全文或 Provider 秘密到 `localStorage`。
- 资料删除、学期归档和本机数据目录治理沿用现有共同底座规则，本 PRD 不建立第二套存储系统。

## 10. Non-Goals

Phase 1.5-T01 不包含：

- SenseVoice、FunASR、FFmpeg 的安装、下载、运行或选型结论；
- 实时字幕、流式识别、浏览器持续录音或课堂直播；
- 说话人分离、教师/学生身份识别、声纹识别或课堂监控；
- 默认云端 ASR 或录音自动上传外部服务；
- 视频抽音轨和手写笔记 OCR 的正式实现；
- 新数据库表、migration、共享类型、API 路由、Job 类型或状态枚举；
- `AuralConverter`、上传服务、Worker、前端路由或页面代码；
- 自动启动 T02–T06。
