# AI StudyBuddy 前端设计指南

**版本**：v1.0
**日期**：2026-07-06
**适用范围**：apps/mobile（React Native / Expo）

> 本文档定义前端的 UI/UX 设计原则、交互规范、导航架构、状态管理策略和性能预算。
> 代码层面的组件规范、命名规范见 dev-rules.md，本文档聚焦"设计决策"。

---

## 一、设计原则

### 1.1 核心理念

| 原则 | 说明 | 反面案例 |
|------|------|----------|
| **极低操作摩擦** | 上课前1秒能开始录音，下课后1秒能上传 | 需要填3个表单才能开始录音 |
| **学生有主体感** | 复习科目、时长、节奏由学生自己定 | 系统强制安排每天必须做几套卷 |
| **进度感可视化** | 错题掌握一道少一道，任务完成有打勾动效 | 冷冰冰的数字统计 |
| **AI是助手不是老师** | AI整理笔记、出题、解析，但不替代思考 | AI直接给答案，学生不用动脑 |
| **家长视角温柔** | 只看完成状态和时间，不看分数对错 | 家长面板显示排名、分数、错题详情 |

### 1.2 设计语言

| 维度 | 决策 | 理由 |
|------|------|------|
| 整体风格 | 简洁、轻量、学习工具感 | 不是社交App，不是游戏，是"数字文具" |
| 色调 | 主色：深蓝 #2563EB，辅助：绿 #10B981（完成）、橙 #F59E0B（待做）、红 #EF4444（超时） | 状态色语义明确，主色沉稳不浮躁 |
| 暗色模式 | 必须支持，且优先适配 | 大学生夜间使用场景多 |
| 字体 | 系统默认字体（iOS: SF Pro, Android: Roboto），数学公式用 KaTeX 渲染 | 不引入自定义字体，减少包体积 |
| 圆角 | 统一 12px（卡片）、8px（按钮）、4px（输入框） | 一致感 |
| 间距 | 基于 4px 倍数：4/8/12/16/20/24/32 | 标准间距系统 |
| 图标 | Lucide Icons（React Native版） | 轻量、统一风格、Tree-shakable |

### 1.3 无障碍

- 所有可点击元素最小触摸区域 44×44pt
- 文字最小字号 14sp，正文 16sp
- 对比度满足 WCAG AA（4.5:1 正文，3:1 大文字）
- 支持系统字号缩放（不锁定 fontScale）

### 1.4 开源产品参考边界

> 详细 SoT：`docs/open-source-foundation.md`

前端可以参考 KaoBuddy 的学习闭环、MiaowTest 的刷题/错题统计、考试粥助手的轻量资料上传体验，但必须保持 AI StudyBuddy 的产品气质：学生主体、低摩擦记录、家长温柔可见。

- 课程资料页可参考 KaoBuddy 的“资料 → 知识点 → 计划 → 模拟考”组织方式。
- 做题页、批改结果页、错题统计可参考 MiaowTest，但不引入排名、竞争、分数羞辱式设计。
- MVP 的上传、笔记、练习、错题追踪可参考考试粥助手，保持一步一闭环。
- 家长端永远只展示任务完成状态、时间、工作量、错题复习数量和掌握趋势，不展示题目、答案、分数、具体错因。
- AI 解题结果页展示“教学解析步骤”，避免包装成不可验证的模型内部思考全文。


## 二、导航架构

### 2.1 导航结构

```
App
├── (auth)                    # 未登录态
│   ├── login                 # 登录
│   ├── register              # 注册
│   └── join-space            # 加入家庭空间（扫码/邀请码）
│
└── (main)                    # 已登录态
    ├── (tabs)                # 底部Tab导航（学生端）
    │   ├── courses           # Tab1: 我的课程
    │   ├── tasks             # Tab2: 我的任务
    │   ├── error-book        # Tab3: 错题本
    │   └── profile           # Tab4: 我的（设置/家庭空间/AI配置）
    │
    ├── course/[id]           # 课程详情（课次列表）
    ├── session/[id]          # 课次详情（录音/笔记/整理结果）
    ├── session/[id]/record   # 课堂记录（录音中...）
    ├── session/[id]/quiz/[qid]  # 做题界面
    │
    ├── homework/new          # 新建作业（拍照/手动）
    ├── homework/[id]         # 作业详情
    │
    ├── past-exam/new         # 上传真题
    ├── past-exam/[id]        # 真题详情（CoT解析）
    │
    ├── mock-exam/[id]        # 模拟考试（限时）
    │
    ├── family/[id]           # 家庭空间（家长视角入口）
    │   ├── timeline          # 任务时间线
    │   └── progress          # 进度趋势
    │
    ├── ai-config             # AI配置页面
    └── settings              # 设置
```

### 2.2 导航规则

| 规则 | 说明 |
|------|------|
| Tab数量 | 4个，不多不少 |
| Tab图标 | 课程（BookOpen）、任务（CheckSquare）、错题本（AlertCircle）、我的（User） |
| 深度限制 | 最多3层（Tab → 列表 → 详情），超过3层用 Modal 或 Sheet |
| 返回行为 | 左上角返回 + Android物理返回键，行为一致 |
| 模态操作 | 新建课程、新建作业等用 BottomSheet，不用全屏页 |
| 家长入口 | 家庭空间页面从"我的"Tab进入，不是独立Tab |

### 2.3 家长端导航

家长登录后，看到的界面不同：

```
App（家长端）
├── (auth)                    # 同上
│
└── (parent)                  # 家长端
    ├── timeline              # 主界面：任务完成时间线
    ├── timeline/detail/[id]  # 某任务的完成详情（只看状态，不看内容）
    ├── progress              # 进度趋势图
    ├── exam-prep             # 备考看板
    └── settings              # 设置（退出空间等）
```

**家长端没有Tab**，因为功能简单——打开就是时间线，左滑看趋势。

## 三、核心页面交互设计

### 3.1 课堂记录页（最频繁使用）

**场景**：学生进入教室，打开手机，开始记录。

```

│  第12课次 · 2026-07-06      │

│   │    🎙️ 开始录音       │   │  ← 大按钮，一键开始
│   └─────────────────────┘   │
│                             │
│   ┌──────┐ ┌──────┐        │
│   │ ✏️   │ │ 📎   │        │  ← 辅助入口
│   │ 笔记 │ │ 链接 │        │
│   └──────┘ └──────┘        │
│                             │
├─────────────────────────────┤
│  本课次已有素材              │
│  • 录音 00:45:12  ✅已上传  │
│  • 笔记 3页               │
│  • 链接 2个               │
├─────────────────────────────┤
│  ┌─────────────────────┐   │
│  │  🤖 一键AI整理        │   │  ← 课后触发
│  └─────────────────────┘   │
└─────────────────────────────┘
```

**交互要点：**
- 录音按钮是页面视觉焦点，足够大（高度 ≥ 56pt）
- 开始录音后按钮变为"录音中..." + 时长计时器 + 波形动效
- 笔记和链接可以在录音过程中随时添加
- 下课后点"一键AI整理"，触发转写 → 笔记 → 思维导图全流程

│  │   ...                │   │
│  └─────────────────────┘   │
│                             │
│  🧠 思维导图                 │

**交互要点：**

- 数学公式用 KaTeX 渲染

- AI处理中显示进度条：`转写中... → 笔记生成中... → 思维导图生成中...`

## 四、离线与弱网策略

| 场景 | 策略 |
|------|------|
| 课堂录音 | 录音存本地，有网自动上传，离线状态角标提示 |
| 查看笔记 | AI整理结果缓存在本地，离线可看 |
| 做题 | 题目预加载，离线可做，有网自动提交 |
| AI整理 | 必须联网，离线时显示"等待网络" |
| 家长面板 | 缓存最后一次加载数据，离线显示"数据更新于 XX:XX" |

**技术实现：**
- 使用 `expo-file-system` 管理本地文件缓存
- 使用 `@react-native-async-storage/async-storage` 存储轻量数据
- 网络状态监听：`@react-native-community/netinfo`
- 上传队列：离线时加入队列，联网后自动消费

## 五、性能预算

### 5.1 启动性能

| 指标 | 目标 | 说明 |
|------|------|------|
| 冷启动到可交互 | ≤ 3秒 | 首屏展示骨架屏，数据异步加载 |
| Tab切换 | ≤ 200ms | 已访问页面保留缓存 |
| 列表滚动 | 60fps | 使用 FlashList 替代 FlatList |

### 5.2 包体积

| 指标 | 目标 | 说明 |
|------|------|------|
| 初始JS包 | ≤ 5MB | Code splitting，按需加载 |
| 图片资源 | ≤ 2MB | 使用 SVG 图标，不用位图图标 |
| 第三方依赖 | 最小化 | 引入前评估体积，避免"为了一个小功能引入大库" |

### 5.3 内存与电量

| 场景 | 策略 |
|------|------|
| 录音 | 分段录音（每10分钟一个文件），避免内存暴涨 |
| 大文件上传 | 分片上传，每片 5MB，支持断点续传 |
| AI处理 | 全部后台处理，前端只轮询状态或等WebSocket通知 |
| 后台省电 | 录音时降低采样率到16kHz，足够ASR用 |

### 5.4 数据加载

| 策略 | 说明 |
|------|------|
| 分页加载 | 列表页默认20条/页，下拉加载更多 |
| 骨架屏 | 数据加载时显示骨架占位，不显示白屏 |
| 乐观更新 | 点赞、状态切换等操作先更新UI，再等后端确认 |
| 图片懒加载 | 列表中的图片进入可视区域再加载 |
| 预加载 | 课次列表预加载最近3个课次的AI整理结果 |

## 六、状态管理策略

### 6.1 状态分层

| 状态类型 | 管理方式 | 示例 |
|---------|---------|------|
| 全局业务数据 | Zustand Store | 用户信息、课程列表、任务列表 |
| 服务端缓存 | React Query (TanStack Query) | API响应缓存、自动刷新、乐观更新 |
| 页面UI状态 | useState / useReducer | Modal显示、表单输入、选中态 |
| 跨页面临时状态 | URL参数 / 路由参数 | 当前选中的课程ID、筛选条件 |
| 持久化数据 | AsyncStorage | Token、用户偏好（暗色模式、语言） |

### 6.2 Store 拆分

```
stores/
├── authStore.ts          # 认证状态（token、用户信息、登录态）
├── courseStore.ts        # 课程列表、当前课程
├── taskStore.ts          # 任务列表、筛选条件
├── quizStore.ts          # 当前做题状态（进度、答案、计时）
├── errorBookStore.ts     # 错题本状态（错题列表、今日复习队列、复习日历、复习进度）
├── familyStore.ts        # 家庭空间、鼓励消息
└── aiConfigStore.ts      # AI配置（本地缓存 + 同步到服务端）
```

### 6.3 数据流

```
用户操作 → Store Action → API调用 → 更新Store → 触发UI重渲染
                              ↓
                         失败时：Toast提示 + 回滚乐观更新
```

**规则：**
- 不在组件内直接调用API，必须通过Store Action或React Query
- 不在Store中存UI状态（Modal、Dropdown等），UI状态留在组件内
- 跨Store通信通过"监听器"模式，不互相import
