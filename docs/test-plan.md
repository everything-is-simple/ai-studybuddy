# AI StudyBuddy 测试计划

**版本**：v1.0
**日期**：2026-07-06
**适用范围**：全项目（前端 + 后端 + AI 服务）

> 本文档定义测试策略、核心测试用例、验收标准和质量门禁。
> 每个开发任务完成后，必须通过对应的验收标准才算完成。

---

## 一、测试策略

### 1.1 测试金字塔

```
         ╱╲
        ╱ E2E╲           少量关键路径（5-10 个）
       ╱──────╲
      ╱ 集成测试 ╲        API + DB 联调（每个模块 10-20 个）
     ╱────────────╲
    ╱   单元测试     ╲    业务逻辑、工具函数（覆盖率 ≥ 80%）
   ╱────────────────╲
```

| 层级 | 工具 | 覆盖目标 | 运行频率 |
|------|------|---------|---------|
| 单元测试 | Vitest | 业务逻辑、AI prompt 解析、工具函数 | 每次提交 |
| 集成测试 | Vitest + supertest | API 端到端（请求→DB→响应） | 每次提交 |
| E2E 测试 | Detox 或 Maestro | 前端关键路径（登录→录音→整理→做题） | PR 合并前 |
| 手动验收 | 人工 | 交互体验、视觉还原、边界情况 | 每个 Phase 结束 |

### 1.2 测试环境

| 环境 | 用途 | 配置 |
|------|------|------|
| 本地开发 | 开发时跑单元测试 | SQLite 内存 + mock AI 服务 |
| CI（GitHub Actions） | 自动跑单元测试+集成测试 | PostgreSQL（testcontainers）+ mock AI |
| 手动验收 | 真机测试 | 完整 docker-compose + 真实 AI 服务 |

### 1.3 测试命名规范

```
describe('模块名')
  it('应该_预期行为_当_条件')

// 示例
describe('AuthService')
  it('应该_返回token_当_手机号和密码正确')
  it('应该_抛出401_当_密码错误')
  it('应该_抛出401_当_用户不存在')
```

### 1.4 开源底座决策回归测试

> 详细 SoT：`docs/open-source-foundation.md`

每次引入或参考开源项目时，必须增加边界测试或审查记录：

| 测试项 | 验收标准 |
|---|---|
| 主架构未漂移 | 仍使用 React Native Expo + Fastify + PostgreSQL/pgvector + Redis/BullMQ |
| 外部能力 Adapter 化 | RAG/ASR/OCR/AI Workflow 只能通过 Provider/Adapter/Worker 接入 |
| 许可证记录 | 复制代码片段必须记录来源 URL、License、修改说明 |
| 家长隐私边界 | 家长 API 和页面不返回题目、答案、分数、具体错因 |
| 错题统一沉淀 | 平时练习、作业、真题、模拟卷错题都进入同一 error-book 流程 |
| AI 解析安全 | 学生端展示教学解析步骤，不保存或展示不可控内部推理全文 |


## 二、单元测试用例

### 2.1 认证模块（auth）

| 测试项 | 输入 | 预期输出 |
|--------|------|----------|
| 注册成功 | 有效手机号 + 验证码 | 返回 user + token |
| 注册重复手机号 | 已注册的手机号 | 抛出 40001 错误 |
| 登录成功 | 正确凭证 | 返回 access_token + refresh_token |
| 登录密码错误 | 错误密码 | 抛出 40001 |
| Token 刷新 | 有效 refresh_token | 返回新 access_token |
| Token 过期 | 过期 refresh_token | 抛出 40001 |
| 验证码过期 | 过期验证码 | 抛出 40001 |

### 2.2 课程与课次模块（courses/sessions）

| 测试项 | 输入 | 预期输出 |
|--------|------|----------|
| 创建课程 | 有效课程名 | 返回 course 对象 |
| 创建课次 | 有效课程 ID + 日期 | 返回 session 对象 |
| 获取课程列表 | 已登录学生 | 返回该学生的课程 |
| 访问他人课程 | 非本人课程 ID | 抛出 40101（权限） |
| 删除课程 | 课程有子数据 | 级联删除课次和素材 |

### 2.3 AI 整理模块（organize）

| 测试项 | 输入 | 预期输出 |
|--------|------|----------|
| 触发整理 | 有录音的课次 | 创建异步任务，返回任务 ID |
| 重复触发 | 已在 processing 的课次 | 返回已有任务 ID（幂等） |
| 转写成功 | 有效音频 URL | transcripts 表写入带时间戳文本 |
| 笔记生成成功 | 转写文本 + 手写笔记 | structured_notes 表写入 Markdown |
| 思维导图生成 | 结构化笔记 | mind_maps 表写入 JSON 树形结构 |
| AI 超时 | 模拟超时 | 重试 2 次后标记 failed |
| AI 返回异常 | 非 JSON 响应 | 标记 failed，记录日志 |

### 2.4 写题模块（quiz）

| 测试项 | 输入 | 预期输出 |
|--------|------|----------|
| 生成练习题 | 有笔记的课次 | 生成 5-10 题的 question_set |
| 提交答案 | 有效答案 JSON | 创建 submission + 触发批改 |
| 选择题批改 | 选项答案 | 精确判对/错 |
| 简答题批改 | 文本答案 | LLM 评分（0-满分） |
| CoT 解析生成 | 题目 | 生成八步思维链 |
| 超时提交 | 超过截止时间 | 标记 overdue，仍可提交但标记迟到 |
| 重复提交 | 同 user + 同 question_set | 更新已有 submission |

### 2.5 错题本模块（error-book）

| 测试项 | 输入 | 预期输出 |
|--------|------|----------|
| 错题自动收集 | 批改结果含错题 | error_questions 自动入库 |
| 错因分类 | 错题 | AI 自动判断错因类型 |
| 复习排程生成 | 新错题 | next_review_date = 明天 |
| 原题重做正确 | 复习第1轮 | consecutive_correct +1 |
| 原题重做错误 | 复习第2轮 | review_stage 重置为 0，consecutive_correct 重置 |
| 变题生成 | 复习第3轮 | AI 生成变题 + 答案 + 解析 |
| 连续3次正确 | consecutive_correct ≥ 3 | status 改为 mastered |
| 复习日历查询 | 未来7天 | 返回每天待复习数量 |

### 2.6 家长可见模块（visibility）

| 测试项 | 输入 | 预期输出 |
|--------|------|----------|
| 家长查看时间线 | 家长 token | 返回完成状态+时间戳（无题目内容） |
| 家长查看分数 | 家长 token | 拒绝或返回空（看不到分数） |
| 家长点赞 | 有效任务 ID | 创建 encouragement 记录 |
| 重复点赞 | 同任务+同家长 | 忽略（幂等） |
| 学生看到鼓励 | 学生 token | 返回收到的鼓励列表 |

## 三、集成测试用例

### 3.1 API 集成测试

| 场景 | 请求链 | 验证点 |
|------|--------|--------|
| 完整录音→整理→查看 | POST recording → POST organize → GET structured-note | DB 状态流转：uploaded → processing → done |
| 完整出题→做题→批改 | POST generate-practice → POST submit → GET grading | question_set + submission + grading_results 关联正确 |
| 错题→复习→掌握 | 做题错误 → 自动入库 → 复习正确×3 → mastered | error_questions 状态流转正确 |
| 家庭空间全流程 | 创建空间 → 家长加入 → 学生做任务 → 家长查看时间线 | 权限隔离正确 |

### 3.2 数据库集成测试

| 场景 | 验证点 |
|------|--------|
| 级联删除课程 | 删除课程后，课次/录音/笔记/整理结果全部删除 |
| 唯一约束 | 重复创建相同邀请码失败 |
| 并发提交 | 两个请求同时提交同一题组答案，只有一个生效 |
| 索引生效 | 大数据量查询使用 EXPLAIN 验证走索引 |

## 四、E2E 测试用例

### 4.1 核心路径

| 路径 | 步骤 | 验收标准 |
|------|------|---------|
| 学生首次使用 | 注册 → 创建课程 → 创建课次 → 上传录音 → 查看 AI 笔记 | 全流程顺畅，2分钟内看到结果 |
| 日常做题 | 打开课次 → 开始练习 → 答题 → 提交 → 查看批改 | 答题流畅，批改 <10 秒 |
| 错题复习 | 做错 → 次日复习 → 做对 → 持续复习 → 掌握 | 复习队列正确，掌握后移出 |
| 家长查看 | 家长登录 → 查看时间线 → 点赞 → 学生看到 | 数据同步正确 |

### 4.2 异常路径

| 路径 | 步骤 | 验收标准 |
|------|------|---------|
| 网络断开 | 录音中断网 → 恢复后自动上传 | 不丢失录音，自动续传 |
| AI 失败 | 触发整理 → AI 服务挂掉 | 显示失败状态，可重试 |
| Token 过期 | 长时间未操作 → 自动刷新 | 用户无感刷新 |

## 六、质量门禁

### 6.1 CI 流水线

```
PR 提交 → Lint 检查 → TypeScript 类型检查 → 单元测试 → 集成测试 → 构建检查
                                                                    ↓
                                                          全部通过 → 可合并
                                                          任一失败 → 阻止合并
```

### 6.2 合并前必须通过

| 检查项 | 要求 |
|--------|------|
| ESLint | 0 errors，warnings ≤ 5 |
| TypeScript | `tsc --noEmit` 0 errors |
| 单元测试 | 100% 通过 |
| 集成测试 | 100% 通过 |
| 新增代码覆盖率 | ≥ 80%（通过 vitest --coverage） |
| 构建 | 前后端均能成功构建 |

### 6.3 发布前必须通过

| 检查项 | 要求 |
|--------|------|
| E2E 测试 | 核心路径 100% 通过 |
| 手动验收 | 当前 Phase 所有验收标准通过 |
| 性能测试 | 首页加载 ≤ 3s，API 响应 ≤ 500ms |
| 安全审查 | 无硬编码密钥、无 SQL 注入风险 |
