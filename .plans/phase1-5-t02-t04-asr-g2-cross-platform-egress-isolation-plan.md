## 3. G2 语义修订

### 3.1 平台无关门禁定义

G2 的目标不是证明“Windows Defender Firewall 存在”，而是证明：

> 在模型、运行时和安全合成输入均已位于本地的前提下，由 ASR 进程外部的操作系统、容器或虚拟化层强制禁止目标运行环境出站联网时，固定版本的 ASR 候选仍可完成受控本地推理；隔离机制、运行期间状态和回滚结果均可审计、可重复、可追溯。

Windows Firewall 只是标准 Windows 上的一种可接受实现。**Windows Firewall 不是 ASR 运行依赖，也不是跨平台产品的固定依赖。**它不是：

- ASR 运行依赖；
- FunASR/SenseVoiceSmall/FSMN-VAD 的技术依赖；
- 跨平台产品必须统一安装的组件；
- 判断 ASR 候选是否识别有效的唯一方法。

### 3.2 G2 在门禁体系中的位置

- G1/G3 负责当前候选的版本可追溯性与核心受控能力事实。
- G2 负责生产发布前的本地离线强制证据。
- G2 未完成不得宣称具备生产发布资格或已证明全部目标平台离线安全。
- G2 环境不可用不得反向写成 ASR 技术选型失败，也不得抹除 G1/G3 已有 `PASS` 事实。
- 本计划不决定 T05/T06 是否可以创建计划或进入实现；任何后续任务仍须独立计划、审查和用户明确批准。

### 3.3 平台范围原则

一次 G2 `PASS` 只对完成验证的明确平台、隔离实现、运行时架构和版本组合有效，不自动外推为“所有平台均已离线验证”。生产发布到新的目标平台或新的隔离实现前，应根据风险决定是否补充该平台证据。

## 4. 统一证据契约

未来任何平台实现只有同时满足以下条件，才可作为 G2 强证据：

1. **外部强制**：隔离由 ASR 进程外部的 OS、容器运行时或虚拟化层执行；应用环境变量、SDK offline/cache-only、DNS 偏好或代码自律不能单独构成 G2 证据。
2. **目标明确**：记录目标 Python/容器/虚拟机/namespace 的精确身份、版本、架构和作用范围，避免影响其他任务或系统进程。
3. **最小临时范围**：隔离必须命名、临时、最小化，并有明确开始/结束边界；不得修改永久系统策略、注册表、系统服务、全局 PATH 或无关网络配置。
4. **本地固定输入**：只使用 G1 已固定且哈希复核的 SenseVoiceSmall 与 FSMN-VAD 快照，以及安全合成、非敏感样例；不得在隔离试验中下载模型或调用真实 Provider。
5. **强制状态证据**：保存隔离前、隔离生效后、ASR 运行期间和清理后的平台原生状态快照。
6. **独立阻断检查**：在隔离生效期间执行不包含秘密和业务数据的受控通用出站探测，预期由隔离层阻断；具体探测目标和方法必须在未来执行计划中提前冻结并单独获批，不得使用真实 Provider。
7. **ASR 正向证据**：在同一隔离窗口内运行固定的最小 ASR 正向样例，并得到结构化成功结果；不得以隔离前缓存输出或预生成转写冒充运行结果。
8. **可回滚**：以 `try/finally` 或平台等价机制清理；记录回滚命令、退出状态和残留计数。清理失败即不得判定 `PASS`。
9. **脱敏与可追溯**：不记录完整转写、真实录音、密钥、Provider URL、完整 UUID 或个人信息；保留运行 ID、短哈希、版本、时间、错误分类和证据文件清单。
10. **可重复**：至少完成计划规定的重复次数；单次偶然成功不能关闭 G2。

## 5. 可接受的平台实现候选

以下是未来可选实现，不代表本计划批准执行，也不要求所有平台同时实施。

### 5.1 标准 Windows

可使用临时 Windows Firewall 出站阻断规则，但必须：

- 至少一个适用 Firewall profile 已启用；
- 在提升权限的会话中执行；
- 规则绑定明确的目标 executable 或等价最小作用域；
- 使用任务专属规则名；
- 保存规则和 profile 的前/中/后快照；
- `finally` 删除规则并确认残留为 0。

缺少有效 profile、权限或可回滚能力时，应分类为 `ENVIRONMENT_UNAVAILABLE`，不得要求启用永久策略或用弱化方案替代。

### 5.2 Linux

可使用临时 network namespace、nftables 或等价 OS 级机制，但必须：

- 为本任务创建独立 namespace/规则集或其他最小隔离作用域；
- 明确禁止出站，同时避免修改无关主机永久规则；
- 保存 namespace、路由、接口和规则集的前/中/后证据；
- 结束后删除任务专属 namespace/规则并确认零残留。

不得把仅修改 `/etc/hosts`、DNS 或应用代理配置作为 G2 强证据。

### 5.3 Docker 或兼容容器运行时

可使用 `--network none` 或语义等价的容器网络隔离，但必须：

- 固定容器镜像标识/摘要和运行命令；
- 将已固定模型以只读方式装入隔离容器；
- 记录容器 network mode、接口/路由状态、运行期探测结果和容器退出状态；
- 删除任务容器及临时挂载，确认无残留。

仅在宿主设置 offline 环境变量、但容器仍有正常网络时，不构成 G2 证据。

### 5.4 独立虚拟机

可在专用虚拟机运行期间由 hypervisor 断开虚拟网卡或切换到不可出站的隔离网络，但必须：

- 记录虚拟机、快照、虚拟网卡和网络模式的明确身份；
- 由宿主/hypervisor 证据证明隔离在 ASR 进程之外生效；
- 隔离期间完成受控出站探测和本地 ASR 正向运行；
- 试验结束恢复原网络状态并记录回滚结果。

人工点击“断网”但没有前后状态和运行期证据，不足以关闭 G2。

### 5.5 其他 OS/虚拟化强制机制

其他机制只有满足第 4 节全部统一证据契约，并在未来独立计划中说明威胁边界、作用域、阻断验证、回滚和残留检查，才可进入评审。不能因为机制名称不同而降低证据强度。

## 6. 状态分类与当前环境结论

### 6.1 状态定义

| 状态                      | 定义                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `PASS`                    | 在明确的平台/架构/隔离实现上，强制隔离、受控阻断探测、ASR 正向运行、可重复性和完整回滚均有可信证据。       |
| `PARTIAL`                 | 已形成部分可信证据，但仍有覆盖、重复性、作用域、资源、异常处理或清理缺口。                                 |
| `ENVIRONMENT_UNAVAILABLE` | 当前环境没有满足证据契约的隔离机制、权限或可回滚条件；这是环境能力不足，不是 ASR 候选失败。                |
| `DEFERRED`                | 已确认当前不在该环境继续执行，等待标准 Windows、Linux、容器或虚拟机等合适环境。                            |
| `FAIL`                    | 隔离未实际生效、受控探测仍可出站、出现非预期联网、来源/哈希不一致、越权永久修改、失控进程或回滚/清理失败。 |
| `BLOCKED`                 | 执行依赖的前置证据或批准缺失，且在当前任务范围内不能继续。历史记录可继续保留该术语。                       |

### 6.2 当前定制 Windows 结论

对当前定制版 Windows 10：

- Domain/Private/Public Firewall profile 均不可用；
- 不要求恢复或启用永久 Firewall 策略；
- 不修改系统服务、注册表、PATH 或永久网络策略；
- 不再把该机器缺少 Windows Firewall profile 解释成 ASR 候选失败；
- 未来正式采用本语义后，该环境的 G2 尝试应记录为 `ENVIRONMENT_UNAVAILABLE / DEFERRED`；
- 既有执行文档中的 `G2=BLOCKED` 保持历史事实，不追溯篡改；跨平台 G2 仍为待补证据，不能标为 `PASS`。

## 7. 未来执行的批准与停止条件

即使本计划 fresh-pass 通过，未来也必须另建执行任务并再次获得用户明确批准。未来执行计划至少冻结：

- 目标平台、版本、架构和隔离机制；
- 精确目标运行时及其独占检查；
- 隔离前/中/后快照命令；
- 受控通用出站探测方法；
- 固定本地模型、样例、运行次数和结构化结果；
- 超时、资源、进程和临时文件清理；
- 回滚命令和零残留判定；
- 允许写入目录与证据清单。

遇到以下任一情况立即停止：

1. 需要修改永久防火墙策略、注册表、服务、系统 PATH 或无关网络配置；
2. 隔离机制无法限定到任务作用域或无法可靠回滚；
3. 需要真实 Provider、真实课堂录音、秘密或业务数据；
4. 目标模型不是 G1 已固定快照或哈希不一致；
5. 受控探测仍可出站，或运行期出现未解释网络活动；
6. 清理后存在规则、namespace、容器、虚拟网卡状态、进程或临时文件残留；
7. 需要扩大到新 ASR/VAD 候选、产品 Adapter、API、Worker 或前端实现。
