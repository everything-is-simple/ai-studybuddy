## 4. 未来实施安全契约

### 4.1 受控日志根、允许子目录与 allowlist

本次及后续同范围实现必须在任何新建、追加、枚举、压缩、轮转、保留判断或清理之前，规范化每一个日志候选路径并建立完整路径段关系（不得使用宽松字符串前缀）：

- **日志根**只能是未来实现显式配置并校验的受控日志根；不得隐式复用仓库根、应用数据根或任意当前工作目录。现有文档中日志拓扑与 `APP_DATA_ROOT` 约定存在交叉时，实施前必须先通过最小化、已批准的规范对齐确定唯一受控根，不能以运行时猜测扩大范围。
- **允许子目录与文件类别**必须是显式、有限、不可由任意外部输入扩展的 allowlist；只能处理实现时定义的运行日志、错误日志、部署/运维日志及其轮转副本。未知目录、未知文件类别与非日志数据默认拒绝。
- **可清理目标**必须同时证明：位于规范化日志根下、属于 allowlist、是可清理的日志类别，并满足未来实施定义的保留策略；日志根本身、其父目录和任何预存/未知目录不得作为递归清理目标。
- 空值、空白、相对路径、无法规范化的路径、`..` 逃逸、仓库根、磁盘/卷根、用户目录、外部 worktree、`APP_DATA_ROOT`、正式数据库、正式数据、备份、模型、部署包输出、staging 目录及其他非日志数据一律拒绝。
- 枚举、轮转与清理前后必须识别符号链接、junction、mount point 和其他重解析点及其解析目标；默认不跟随、不作为处理目标。若无法可靠判断，必须以固定错误类别拒绝，不能降级为递归处理。

### 4.2 内容脱敏与最小记录原则

本次及后续同范围实现必须以字段 allowlist 为基线，而不是尝试记录完整对象后再事后过滤：

- 日志字段只保留为诊断所必需的固定事件类型、稳定错误码/分类、受限操作类别、非敏感短标识、时间、耗时和允许的状态摘要；实际字段表须在实施时固定并受测试约束。
- API Key、token、密码、Cookie、完整 Webhook、Provider URL、环境变量值、完整宿主环境、真实学生资料、资料/笔记/答案全文、完整文件内容、原始请求/响应体、完整 UUID、真实路径及外部服务原始响应不得记录。
- 异常消息、`cause` 链、stack、子进程 stdout/stderr、原始命令输出与诊断对象必须默认视为不可信输入；只能归类为固定脱敏码/摘要，不得原样拼入日志或公开错误。
- 请求/响应元数据只允许经明确字段 allowlist 的非敏感最小摘要；不得以调试、失败重试、运维或测试便利为由记录正文、头、Cookie、认证信息、文件内容或个人信息。
- 任何脱敏失败、不确定字段或无法序列化的诊断信息必须 fail closed：记录固定类别而不是回退到 `String(error)`、对象 dump、环境 dump 或原始输出。

### 4.3 轮转、保留与清理拒绝/错误契约

未来实现的操作前置条件与错误输出必须可测试：

- 只有已规范化并通过日志根/allowlist/非重解析点校验的合成测试日志文件，才能成为未来轮转、保留或清理的候选；其他目标必须在递归枚举、删除或内容读取之前拒绝。
- 未来固定错误分类可采用 `LOG_ROOT_INVALID`、`LOG_TARGET_EMPTY`、`LOG_TARGET_OUTSIDE_ALLOWLIST`、`LOG_TARGET_PROTECTED_ROOT`、`LOG_TARGET_REPARSE_POINT`、`LOG_RETENTION_INVALID`、`LOG_CONTENT_REDACTED` 等形式；具体命名待实施时统一，但不得携带绝对路径、环境、stack、命令输出、文件内容或秘密。
- 面向调用者、控制台和测试断言的错误消息只能返回固定、脱敏、非绝对路径的错误码/类别；内部诊断也不得通过另一日志通道回显被禁止的原始值。
