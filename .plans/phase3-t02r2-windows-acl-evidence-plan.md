## 1. 唯一目标与完成口径

在一台经明确批准的 Windows 机器和指定安装实例上，对 `config`、`data`、`logs`、`backups`、`tmp`、`models` 六个**逻辑目录类别**生成一次只读、脱敏的 ACL 风险证据。每类别结论只允许表达：目录/根边界状态、ACL 是否可读、继承状态、allow/deny 与显式/继承 ACE 的聚合数、固定主体类别聚合、reparse 风险、有效访问是否未知、风险等级和是否建议另建最小 ACL 修复任务。

T02-R2 仅在全部六类均在批准目标上实际读取，或每个缺失/不可读类别有固定的脱敏 `UNKNOWN`/风险结论，并且无未处置 P0/P1 时完成。合成夹具、开发机、安装检查的“ACL readable”文案或单一目录结果都不构成真实 R2 完成。

## 2. 真实目标机门禁

真实读取前必须由用户或受权审查者提供并在受控、非仓库证据中签收：

- 目标机器脱敏别名、安装实例脱敏别名、构建提交短哈希、artifact ID、包 SHA-256 短指纹和采证时间窗口；
- 明确仅允许六个逻辑类别，且其物理根由脚本从经批准的安装实例推导，不能由任意路径参数替代；
- 当前交互用户具备只读 ACL 查询权限；没有管理员提权、远程执行、服务停启、计划任务创建或运行时配置修改；
- 同一时间窗口内不把 Alpha、其他机器、其他包、其他安装实例或旧合成夹具证据冒充本任务结果。

缺少任一项、目标身份不匹配、逻辑根边界无法验证、路径不存在/不可读、发现 reparse 风险或无法安全分类时，脚本只返回固定脱敏状态和风险结论；不尝试修复、重试写入、扩大扫描或读取其他路径。

## 4. 脱敏字段与风险规则

允许的可观察字段仅为：目标/安装脱敏别名、artifact ID、构建短哈希、包 SHA-256 短指纹、批准窗口标识、逻辑类别、固定状态/风险码、固定主体类别、allow/deny、显式/继承与数量聚合、继承保护布尔值、reparse 风险布尔值、`EFFECTIVE_ACCESS_UNKNOWN` 和是否建议另建修复任务。

禁止出现：绝对路径、相对敏感文件名、ACL 原文、owner/ACE 原文、完整 SID、用户名/域名/计算机名、完整 UUID、环境变量、文件内容、原始 PowerShell 命令或 transcript、堆栈、底层异常、真实资料/日志/备份内容。

风险结论规则：任一 `UNKNOWN`、deny ACE、未知主体、继承异常、reparse 风险或有效访问未知都不得被解释为“安全”；须按类别记录 P1 风险或最小修复建议，并阻断任何 T04-3 目标机真实 backup/restore 写入。只有未来独立、最小、可回滚的 ACL 修复任务才能写 ACL。

## 7. 独立审查 P1 修订（2026-07-28）

本节由独立审查结论触发，并**覆盖第 2～6 节中与本节冲突的任何表述**；未列出的范围和禁止项继续有效。修订后仍不授权实现、真实采证、ACL 修复或任何写入。

### 7.1 真实运行时根边界与 no-follow

- 真实运行时只允许对 `Get-AIStudyBuddyPaths` 导出的六个根目录本身进行元数据与 ACL 查询；禁止 `-Recurse`、任何子项枚举、目录清单快照、文件内容读取、哈希及目录树前后比对。
- 实现必须先通过不跟随 reparse 的目录句柄确认根属性，并只从同一 no-follow 句柄读取安全描述符。不得把“先检查属性、再以普通路径调用 `Get-Acl`”视为安全保证。
- 当前 PowerShell/.NET 环境不能证明 no-follow 读取，或根已是/变为 reparse 时，必须输出 `ACL_EVIDENCE_NOFOLLOW_UNSUPPORTED` 或 `REPARSE_RISK`，不得回退为普通路径式 ACL 查询。
- 删除原计划中真实目标机“运行前后检查六类根没有变更”的运行时要求；只读保证只可由源码命令 allowlist/denylist 静态测试和仓库外合成夹具无写入回归证明。真实证据只能记录固定 `READ_ONLY_OPERATION_SET_VERIFIED` 状态。

### 7.2 主体分类与禁止的系统查询

- 入口和帮助函数不得调用服务、计划任务、任务注册表或相关控制/查询 API，包括 `Get-ScheduledTask`、`schtasks`、`Get-Service`、`Start-Service`、`Stop-Service`、`Restart-Service`。
- 主体仅可基于当前 Windows 身份、SYSTEM 与 Administrators 的固定 SID 映射归类；其他本地/域主体或不能安全归类的 ACE 必须为 `UNKNOWN`。
- 不得把当前交互用户 ACE 推断为“当前用户计划任务”；该类别在未进行禁止的计划任务查询时只能标记为未评估/未知。有效访问仍一律按 `EFFECTIVE_ACCESS_UNKNOWN` 处理。

### 7.3 结构化元数据 schema

所有真实目标机输入和可观察证据在使用及序列化前必须二次验证：

- `artifactId`：8–64 位，且只允许 `[A-Za-z0-9][A-Za-z0-9._-]*`；
- 目标机器别名、安装实例别名和批准窗口 ID：只能使用预批准的 8–32 位 `[A-Z][A-Z0-9_-]*` opaque 值，不接受主机名、域名、用户名、路径、完整 UUID 或自由文本；
- 构建短哈希和包 SHA-256 短指纹：固定 12 位小写十六进制；
- 任一不合格输入只返回固定错误码，绝不回显原值。

专项测试必须将路径、换行、动态用户名/SID、完整 UUID 和合成敏感值作为 alias/artifact 输入，证明输出、异常和断言均不回显它们；同时静态断言入口和帮助模块不含递归枚举、内容读取、哈希、ACL 写入、服务或计划任务查询/控制命令。
