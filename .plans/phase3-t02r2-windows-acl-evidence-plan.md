## 1. 唯一目标与完成口径

在一台经明确批准的 Windows 机器和指定安装实例上，对 `config`、`data`、`logs`、`backups`、`tmp`、`models` 六个**逻辑目录类别**生成一次只读、脱敏的 ACL 风险证据。每类别结论只允许表达：目录/根边界状态、ACL 是否可读、继承状态、allow/deny 与显式/继承 ACE 的聚合数、固定主体类别聚合、reparse 风险、有效访问是否未知、风险等级和是否建议另建最小 ACL 修复任务。

T02-R2 仅在全部六类均在批准目标上实际读取，或每个缺失/不可读类别有固定的脱敏 `UNKNOWN`/风险结论，并且无未处置 P0/P1 时完成。合成夹具、开发机、安装检查的“ACL readable”文案或单一目录结果都不构成真实 R2 完成。

## 2. 真实目标机门禁

真实读取前必须由用户或受权审查者提供并在受控、非仓库证据中签收：

- 目标机器脱敏别名、安装实例脱敏别名、构建提交短哈希、artifact ID、包 SHA-256 短指纹和采证时间窗口；
- 明确仅允许六个逻辑类别，且其物理根由脚本从经批准的安装实例推导，不能由任意路径参数替代；
- 当前交互用户具备只读 ACL 查询权限；没有管理员提权、远程执行、服务停启、计划任务创建或运行时配置修改；
- 同一时间窗口内不把 Alpha、其他机器、其他包、其他安装实例或旧合成夹具证据冒充本任务结果。

缺少任一项、目标身份不匹配、逻辑根边界无法验证、路径不存在/不可读、发现 reparse 风险或无法安全分类时，脚本只返回固定脱敏状态和风险结论；不尝试修复、重试写入、扩大扫描或读取其他路径。

## 3. 拟议最小实现

1. 在 `scripts/lib/AIStudyBuddy.Deployment.psm1` 中新增仅只读的 ACL 采证帮助函数：
   - 从 `Get-AIStudyBuddyPaths` 导出的六类根生成固定清单，不接受任意目录集合；
   - 以 no-follow 方式检查根和可见子项的 reparse 属性，不读取文件内容、不跟随 reparse、不计算或输出物理路径；
   - 使用 `Get-Acl -LiteralPath` 读取 ACL，内部将 owner/ACE 主体归入固定类别：当前交互用户、当前用户计划任务、SYSTEM、Administrators、其他本地用户、未知主体；只保存类别、allow/deny、继承状态和聚合数；
   - 对不能安全推断的有效访问一律输出 `EFFECTIVE_ACCESS_UNKNOWN`，不虚构“可写/不可写”结论；ACL 读取失败或身份转换失败归为 `UNKNOWN`，不泄露底层错误。
2. 新增显式的只读采证入口（建议 `scripts/collect-windows-acl-evidence.ps1`）：
   - 只接受经批准安装实例和第 2 节所述非敏感 artifact 元数据；输出结构化摘要；
   - 禁止 `Set-Acl`、`icacls` 修改模式、`New-Item`、`Remove-Item`、写探针、备份/恢复调用、服务/计划任务控制和网络调用；
   - 运行前后以可审查的只读防护断言确认没有创建、修改或删除六类根中的任何内容；防护结果只输出逻辑类别和固定状态。
3. 新增仓库外合成夹具的只读专项测试（建议 `scripts/test-acl-evidence-boundary.ps1`），并仅在必要处补充 `packages/backend/test/deployment-powershell-compatibility.test.mjs`：验证六类固定清单、路径拒绝、reparse 不跟随、固定主体分类、deny/继承聚合、`UNKNOWN` 与无路径/无 SID/无 ACL 原文输出。
4. 真正目标机运行的证据不提交仓库。`docs/04` 最终只登记 artifact ID、提交短哈希、包短指纹、目标别名、时间窗口、六类逻辑类别聚合、风险结论与是否需要后续最小 ACL 修复任务。

## 4. 脱敏字段与风险规则

允许的可观察字段仅为：目标/安装脱敏别名、artifact ID、构建短哈希、包 SHA-256 短指纹、批准窗口标识、逻辑类别、固定状态/风险码、固定主体类别、allow/deny、显式/继承与数量聚合、继承保护布尔值、reparse 风险布尔值、`EFFECTIVE_ACCESS_UNKNOWN` 和是否建议另建修复任务。

禁止出现：绝对路径、相对敏感文件名、ACL 原文、owner/ACE 原文、完整 SID、用户名/域名/计算机名、完整 UUID、环境变量、文件内容、原始 PowerShell 命令或 transcript、堆栈、底层异常、真实资料/日志/备份内容。

风险结论规则：任一 `UNKNOWN`、deny ACE、未知主体、继承异常、reparse 风险或有效访问未知都不得被解释为“安全”；须按类别记录 P1 风险或最小修复建议，并阻断任何 T04-3 目标机真实 backup/restore 写入。只有未来独立、最小、可回滚的 ACL 修复任务才能写 ACL。

- 全程未使用 ACL 写入或文件写探针，夹具前后状态证明无内容/ACL 变更；
- 至少运行新的 ACL 专项测试、既有 `scripts/test-data-boundary.ps1`、`pnpm type-check`、backend build、frontend build、设置隔离 `APP_DATA_ROOT` 的 `pnpm test`、文档治理和 `git diff --check`。
