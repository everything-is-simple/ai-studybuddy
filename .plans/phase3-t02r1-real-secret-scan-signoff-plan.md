## 1. 唯一目标与完成口径

在不泄露秘密、内容、绝对路径、敏感相对文件名或原始终端输出的前提下，对两类**显式、可审计输入**执行一次确定性扫描并形成脱敏签收：

1. 当前提交的 Git 已跟踪文件清单；
2. 经人工批准的、单一、已识别的候选部署包目录根。

只有两类输入均已实际完成、无 P0 或 P0 已按条件流程闭合，且证据字段满足第 4 节，T02-R1 才可标记完成。仅完成脚本、单元测试、仓库扫描或合成包扫描均不构成 R1 完成。

## 2. 不可逾越的输入与停止门

### 2.1 Git 跟踪文件

- 唯一来源是目标提交工作树内 `git ls-files -z` 的结果；不得递归枚举仓库根、工作区、用户目录或磁盘根。
- 清单在扫描前记录提交短哈希、文件计数和扫描器版本；任何未跟踪、忽略、仓库外、子模块外或无法归一化的条目均不在候选集。
- `.env.local`、`production.env`、超限文件、非文本文件、符号链接/reparse point 均由既有安全库在内容读取前跳过或拒绝；跳过只以聚合计数证明。

### 2.2 候选部署包

- 必须由用户或受权审查者预先签发一份**外置、显式、单一**的批准记录，记录 artifact ID、完整构建提交、包 SHA-256 短指纹、明确的逻辑“候选包目录根”及起止时间窗口；签收入口只接受该记录，不接受可替换的行内候选根或元数据参数，也不得搜索、猜测或挑选包。
- 本任务只接受可访问的目录根，不接受 zip 自动解压、网络位置、用户数据根、运行中安装根、备份根、日志根或临时根。目录清单仅在该经批准根内以 fail-closed 方式生成；reparse point、敏感环境文件、非文本文件和超限文件不读取。
- 候选包的构建提交必须与批准记录可比对；若不一致、路径不可验证、根外解析、manifest 缺失/不一致或窗口过期，输出固定失败码并停止，不产生“通过”结论。

### 2.3 绝对禁止

- 不扫描整个工作区；不读取、枚举、移动、删除或提交任何未跟踪目录。实现只基于 Git 已跟踪清单与人工批准的单一候选包根，不得通过目录遍历发现其他输入。
- 不扫描真实环境文件、`APP_DATA_ROOT`、正式数据、学生资料原文、日志、备份、模型、外部 worktree、用户目录或运行时安装目录。
- 不调用 Provider、SMTP、Webhook、OCR、whisper.cpp、网络服务；不修改 ACL、备份/恢复、业务 Schema/API/前端或部署运行行为。

## 7. 独立审查 P1 修订（2026-07-28）

本节由独立审查结论触发，并**覆盖第 1～6 节中与本节冲突的任何表述**；未列出的范围和禁止项继续有效。修订后仍不授权实现、真实扫描、候选包读取或任何其他 Phase 3 工作。

### 7.1 批准提交与 Git 输入一致性

- 单项批准和真实运行前必须给出批准提交的完整 40 位小写十六进制 SHA；入口在任何内容读取前验证 `HEAD` 与该 SHA 精确相等，且该对象存在并可解析。
- 入口还必须以不输出文件名的静默 Git 比较验证已跟踪文件相对该批准提交不存在 staged 或 unstaged diff；验证不得使用 `git status` 或任何会枚举未跟踪/忽略项的命令。任一不一致、Git 错误或无法验证都只输出固定边界错误码并停止。
- 只有上述门禁全部通过后，才可从 `git ls-files -z` 获得已跟踪候选清单；不允许读取工作树中未被批准提交身份锁定的内容。
- 候选包 manifest 中的构建提交也必须为同一完整 40 位小写十六进制 SHA，并与批准值精确相等。完整 SHA 只在内存比较；任何可观察证据仅可使用其固定 12 位小写展示短哈希。

### 7.2 完整扫描覆盖与阻断规则

- 每个候选输入项只能处于“已扫描”、“明确阻断，未扫描”或“经独立、逐项批准的替代安全检查覆盖”之一；签收汇总必须可证明三类数量之和等于候选输入总数。
- 任一 skipped、unreadable、sensitive basename、non-text、oversize、symlink/reparse、归一化失败、根外解析或扫描器异常都必须归为明确阻断并产生 `BLOCKED_UNSCANNED_INPUT`（或更具体的固定边界错误码）。存在任何阻断项时不得产生通过/签收结论。
- “替代安全检查覆盖”必须在真实运行前以独立批准记录逐项列明稳定的无敏感标识与覆盖规则；没有该记录不得将任何被阻断项计为覆盖。不得以聚合“跳过”计数、默认允许或扫描器成功退出替代完整覆盖。
- 候选包仅可遍历经人工批准的单一包根本身；该根必须在仓库外，且重解析/符号链接、根外解析或无法证明边界的项一律阻断。入口不得搜索、猜测、合并多个根或通过工作区遍历寻找候选包。

### 7.3 结构化元数据与脱敏边界

所有批准输入与可观察证据在使用及序列化前必须二次验证：

- `artifactId`：8–64 位，且只允许 `[A-Za-z0-9][A-Za-z0-9._-]*`；
- 批准提交 SHA 与 manifest 构建提交 SHA：固定 40 位小写十六进制；展示短 SHA：固定 12 位小写十六进制；
- 包 SHA-256 短指纹：固定 12 位小写十六进制；
- 批准窗口 ID：只能使用预批准的 8–32 位 `[A-Z][A-Z0-9_-]*` opaque 值，不接受路径、换行、主机名、用户名、完整 UUID 或自由文本；
- `PackageRoot` 只作为一次性执行输入，不得写入 JSON、控制台、异常、断言、日志、证据或版本控制；任一不合格元数据或路径边界只返回固定错误码，绝不回显原值。

### 7.4 修订后的测试与真实签收门禁

- 合成测试必须覆盖批准 SHA 与 `HEAD` 不匹配、已跟踪 staged/unstaged 改动、manifest SHA 不一致、非法 artifact/window/hash 元数据及候选根越界，且确认输出、异常和断言均不回显路径、文件名、原值或合成哨兵。
- 合成夹具必须逐一覆盖 skipped/unreadable/sensitive/non-text/oversize/reparse 等输入，断言它们均为 `BLOCKED_UNSCANNED_INPUT` 且无法生成 pass；同时覆盖“无独立逐项批准的替代检查”不能闭合覆盖。
- 测试只可使用仓库外隔离临时根及无效合成哨兵；合成测试、扫描器实现或结果绝不能表述为真实仓库扫描、真实候选部署包签收或真实生产证据。
- 真实签收仅在批准提交、单一候选包根、manifest、逐项替代检查记录（如有）和本节 schema 全部齐备后才可开始；任何未扫描或未覆盖输入、P0、边界错误或脱敏契约破坏均保持 T02-R1 未完成。
