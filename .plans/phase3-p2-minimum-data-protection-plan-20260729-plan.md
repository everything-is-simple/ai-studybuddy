## 3. 推荐的个人版最小数据保护模型

### 3.1 模型结论

采用**本地、显式触发、白名单 payload、独立 manifest、内容哈希、只读预检、默认拒绝写恢复**模型。它保留个人单机所需要的可验证数据保护基础，而不引入云端、网络、后台服务、自动调度或企业密钥基础设施。

既有 T02G 合成边界是本计划的唯一既有技术前提：只允许 `studybuddy.db` 与 `semesters/` 学习数据白名单；输出根须显式传入、既存、位于安装根之外；非 `-WhatIf` 恢复固定拒绝 `RESTORE_WRITE_DISABLED`。该前提不得被 P2 放宽。

### 3.2 源数据白名单与排除项

未来合成实现和未来受控真实运行均只能以**逻辑白名单**表达 payload：

| 可进入 payload 的逻辑项 | 允许条件 |
| --- | --- |
| `studybuddy.db` | 仅位于已验证数据根的预定义位置；为常规文件；同一 no-follow 读取链路前后身份不变 |
| `semesters/` | 仅位于已验证数据根的预定义位置；每个组件均无 reparse；枚举规则、文件类型与版本契约明确 |

明确不得进入 payload、manifest、日志或错误正文的内容包括：`config/`、`logs/`、`tmp/`、`models/`、缓存、浏览器证据、部署包、staging、`.git`、`node_modules`、环境文件、密钥、运行时 socket/PID、任何工作区文件、未知新增项及白名单外目录。

### 3.3 受保护根、输出根与卷规则

未来实现必须至少区分下列逻辑根，且均不得以字符串前缀代替身份校验：

- **安装根、数据根、仓库根、worktree 根、`APP_DATA_ROOT`、用户目录、卷根**：受保护根；不可作为备份输出根，也不可被测试夹具或清理逻辑触碰。
- **备份输出根**：由用户为一次操作显式指定、已存在、位于安装根之外、与受保护根不重叠的受控目录；不能使用默认输出路径或相对路径。
- **合成测试根**：在仓库外新建的随机测试根，仅包含无意义测试哨兵；测试前后以精确白名单核验。

备份输出根必须与安装/数据根位于同一固定本地卷；不同卷、UNC、映射盘、远程卷、非固定本地卷、卷类型未知或跨卷关系不明均为 `DP_VOLUME_UNSAFE`。同时必须拒绝：路径为空或相对、卷根、无法规范化、输入/输出相交、路径解析前后改变、任何组件为 reparse point、已有未知内容或身份不可验证。跨卷备份不属于个人版最小闭环；如日后确有需要，必须另立计划、独立审查并明确原子性与中断语义，不能静默放宽。

### 3.4 manifest、哈希与脱敏

推荐备份根内一份版本化 manifest 和一个只含白名单 payload 的目录/归档结构。manifest 只包含运行恢复预检所需的最小、非敏感事实：

- schema/version；
- 不含主机路径的逻辑 payload 名称（仅 `studybuddy.db`、`semesters` 及其受控逻辑相对项）；
- payload 的大小、算法标识和**完整** SHA-256 摘要（仅供机器验证，不进入普通控制台输出）；
- 备份格式版本、创建时间（受控粒度）和固定工具/契约版本；
- 不可反推宿主路径、用户名、内容、环境或秘密的随机 artifact ID。

完整 SHA-256 仅留在受控 manifest/机器比较路径；普通输出只可显示规则/错误码、计数、逻辑类别、随机 artifact ID、工具版本和必要时的不可反推短关联 ID。不得输出原始路径、文件内容、完整 hash、数据库字段、用户名、环境变量或原始底层异常。

### 3.5 覆盖、保留与回滚原则

P2 最小闭环不建立长期保留系统。每次成功备份必须创建一个新的、唯一的输出单元；禁止覆盖或递归清理既有备份。普通 P2 合成实现只可清理本次创建、由随机操作 ID 绑定、且预先精确核验的合成 fixture；不得清理真实输出根。真实保留、删除、配额、迁移或跨卷复制均留待独立计划。

## 4. T04-1：最小受控备份契约

### 4.1 触发与前置 Gate

真实受控备份只有在将来单独批准的“真实备份与完整性检查运行”切片中才可执行。届时每次运行必须在操作前显示并获得用户对以下具体事实的确认：目标机器、完整 Git 对象 ID/工具版本、逻辑白名单、已验证的安装/数据/输出根身份、固定本地卷策略、时间窗口和仅脱敏输出契约。

普通 P2 合成实施仅能使用内存或仓库外新建合成 fixture；它不应接受真实目录、默认路径、环境变量 fallback 或未受控命令行目标。

### 4.2 输出结构与原子性

未来实现必须：

1. 先校验全部输入/输出根、卷类型、reparse、身份和白名单，失败时尚未创建任何输出；
2. 在已验证输出根内创建仅本次操作可识别的临时单元；
3. 使用同一 no-follow/身份复核策略读取每个白名单组件，并在复制前后复核源、父目录和输出单元；
4. 完成每个 payload 的哈希后写入临时 manifest；
5. 只有所有 payload 和 manifest 均通过，才以本地原子 rename/publish 方式交付新的备份单元；
6. 失败时只清理经操作 ID、父根身份和新建时间三重核验的临时合成单元；任何不确定情形保留现场并报脱敏失败码。

不得覆盖已有备份、向安装/数据根写入、修改源数据、修改 ACL、创建网络输出、调用服务或计划任务。

### 4.3 失败码（未来实现的最小稳定类别）

| 错误码 | 含义 |
| --- | --- |
| `DP_INPUT_NOT_APPROVED` | 输入或输出未被本次受控运行明确批准 |
| `DP_PROTECTED_ROOT` | 输入/输出与受保护根、卷根或彼此重叠 |
| `DP_VOLUME_UNSAFE` | UNC、映射盘、远程/非固定/未知卷或卷关系不满足契约 |
| `DP_REPARSE_RISK` | 任意待访问组件、父组件或解析目标存在/疑似 reparse |
| `DP_SOURCE_IDENTITY_CHANGED` | 读取前后源、父目录或安装实例身份无法证明一致 |
| `DP_OUTPUT_IDENTITY_CHANGED` | 临时/最终输出单元或其父目录身份改变/不可证明 |
| `DP_PAYLOAD_NOT_ALLOWED` | 白名单外、文件类型异常、遗漏或枚举语义异常 |
| `DP_BACKUP_PUBLISH_FAILED` | 复制、哈希、manifest 或原子发布失败；原始原因不外显 |
| `DP_CLEANUP_UNCERTAIN` | 失败后无法证明清理目标仅属于本次临时单元 |

## 5. T04-2：完整性检查契约

完整性检查是独立、只读的验证路径；它不以“能读取”推断“可恢复”，不修复、不重写 manifest/payload，也不读取源用户数据。

### 5.1 固定验证顺序

未来实现必须按顺序 fail-closed：

1. 验证候选备份根是本次批准的受控根下单一备份单元，且不是受保护根、卷根、UNC、映射盘、远程/未知卷或 reparse；
2. 验证 manifest 是唯一预期文件、大小/格式/版本在受支持的上限内，且严格 schema 解析；
3. 拒绝未识别 schema/工具/算法版本、重复逻辑项、额外 payload、路径穿越、绝对路径、空组件、链接或不支持文件类型；
4. 用 manifest 的逻辑白名单逐项定位 payload，在每个组件的同一 no-follow 读取策略下验证父项与对象身份稳定；
5. 重新计算 SHA-256 并与 manifest 中完整摘要以常量时间/等价安全比较策略匹配；
6. 复核大小、总量限制和目录结构；
7. 仅在所有检查通过后返回 `DP_INTEGRITY_OK` 的脱敏摘要。

### 5.2 必须拒绝的异常

以下任一情况都必须结束为固定类别，不能降级为 warning：manifest 缺失、重复或不合法；未知版本/算法；缺项、额外项、路径穿越；哈希或大小不匹配；读取过程中身份/父目录/内容变化；reparse；卷不安全；无权限或有效访问未知；原始异常；资源上限超限；无法证明输出是预期受控备份。

| 错误码 | 含义 |
| --- | --- |
| `DP_MANIFEST_INVALID` | 缺失、解析失败、schema/版本/字段或重复项不合法 |
| `DP_BACKUP_PATH_UNSAFE` | 备份根、payload 路径、卷或 reparse 边界不安全 |
| `DP_PAYLOAD_STRUCTURE_INVALID` | 逻辑项、文件类型、目录结构、路径或大小限制不匹配 |
| `DP_INTEGRITY_MISMATCH` | payload/manifest 的 SHA-256 或大小不一致 |
| `DP_VERIFICATION_RACE` | 验证过程中的对象、父对象、内容或描述符身份改变 |
| `DP_ACCESS_UNKNOWN` | 无法证明只读访问或身份/访问结果未知 |

允许输出：成功/失败类别、规则版本、计数、随机 artifact ID、逻辑类别与不可反推短关联 ID。绝不允许输出：原始备份路径、宿主路径、完整 hash、文件内容、数据库内容、用户名、SID、环境变量、原始异常/stack 或真实候选名称。

## 6. T04-3：恢复分层与写入 Gate

### 6.1 仅允许规划的只读恢复预检

未来普通 P2 合成实现可规划且只能在合成 fixture 中测试：manifest/payload/路径/hash 预检，恢复目标身份与受保护根交叉检查，恢复计划的脱敏摘要，以及“若写入则必须拒绝”的固定结果。预检不创建目录、不复制文件、不修改属性、不停止服务、不创建 recovery point，且非 `-WhatIf` 路径必须继续固定拒绝：

```text
RESTORE_WRITE_DISABLED
```

### 6.2 真实恢复写入的独立后续 Gate

真实恢复写入绝不属于本计划，也不因后续“P2 合成实现”或“真实备份与完整性检查运行”而获得授权。它至少需要一个新的、单独计划、独立审查和用户逐项批准的切片，并在每一次真实运行前完成：

1. 精确目标机器、安装实例、数据根、候选备份和恢复窗口的用户确认；
2. 已通过的只读完整性检查和无敏感泄露的脱敏签收；
3. 服务/计划任务状态的独立只读确认与批准的停止方案；
4. 写前 recovery point（现有数据的可验证保护）和容量检查；
5. 目标/父目录同一安全句柄、no-follow、卷、reparse、ACL/有效访问和身份稳定性 Gate；
6. 临时恢复单元、可证明的原子切换顺序、断电/中断处理与不确定状态停止策略；
7. 写后 manifest/payload/hash 再验证、服务恢复、只读健康检查和失败回滚策略；
8. 仅脱敏的 pre-write、post-restore、回滚或未知状态证据。

任何一个 Gate 未证明时，不写入、不删除、不覆盖、不调用服务、不尝试修复后继续。

### 8.3 合成与真实证据边界

合成 fixture 必须在仓库外新建随机根，只包含无意义 byte/text 哨兵和测试专用 manifest；不得含真实姓名、课程、资料、秘密、环境、日志或数据库。测试前后必须证明受保护哨兵不变；若 reparse/卷类夹具无法可靠构造，结果只能是 `unsupported`/阻断，不得省略后声称已覆盖。

真实环境验收只能在另行批准的时间窗口内、以用户明确指定机器和目标为限。它不属于本计划、未来合成实现或一般 CI 测试。

## 9. 最小测试矩阵（仅供未来合成实施）

| 类别 | 合成情形 | 必须结论 |
| --- | --- | --- |
| 合法 fixture | 白名单 `studybuddy.db` + `semesters/`、合法受控输出、匹配 manifest/hash | 只返回脱敏 `DP_INTEGRITY_OK` 或对应合成成功类别；无真实访问 |
| 篡改 | payload、manifest、schema、版本、大小、SHA-256 任一篡改 | `DP_MANIFEST_INVALID`、`DP_PAYLOAD_STRUCTURE_INVALID` 或 `DP_INTEGRITY_MISMATCH`；不修复 |
| 路径 | 绝对项、`..`、重复项、额外项、输出与保护根相交 | `DP_BACKUP_PATH_UNSAFE`/`DP_PROTECTED_ROOT`；零写入 |
| reparse/卷 | reparse、UNC、映射盘、远程/非固定/未知卷、跨卷不明 | `DP_REPARSE_RISK` 或 `DP_VOLUME_UNSAFE`；不能建夹具即标阻断 |
| 替换竞争 | 源、父、临时输出、最终输出、payload 或 manifest 在前后检查间替换 | `DP_SOURCE_IDENTITY_CHANGED`、`DP_OUTPUT_IDENTITY_CHANGED` 或 `DP_VERIFICATION_RACE`；不发布/不恢复 |
| 重复与失败清理 | 再次同 ID、已存在未知输出、复制/发布失败、清理对象身份未知 | 拒绝覆盖；仅清理可证明属于本次的合成临时单元，否则 `DP_CLEANUP_UNCERTAIN` |
| 脱敏 | 成功、错误、异常模拟、日志/输出序列化 | 不含路径、文件名、内容、完整 hash、环境、SID、stack 或原始异常 |
| restore preflight | 合法与恶意 synthetic backup 的 `-WhatIf` | 仅预检；无目录/文件/属性变化；非 `-WhatIf` 为 `RESTORE_WRITE_DISABLED` |
| 无真实数据 | 测试参数、fixture 内容、受保护哨兵和访问记录 | 证明只涉及新建合成根/内存 fixture，未读取真实数据或未跟踪目录 |

测试结论必须按“通过/拒绝/unsupported/未知”记录，不能把未覆盖或 unsupported 写作通过。
