## 2. 执行原则与安全门禁

1. 每一 Wave 都从最新 `master` 新建独立任务分支和独立 `.plans/` 实施计划；一个实施任务只覆盖一个可验收结果，避免巨型跨域变更。
2. 先写测试和验收矩阵，再写实现；后端接口优先使用真实 SQLite 集成测试，不 mock DB。
3. 所有会写数据的验证必须设置仓库外 `APP_DATA_ROOT`，使用唯一 task-id；不得触及真实学生数据。
4. 真实 Windows ACL 任务先只读采证；需修改 ACL 时，先记录现状、最小授权、回滚步骤并取得该任务的额外批准。不得改 Firewall、组策略、注册表或永久安全策略。
5. 真实恢复写入必须先具备：服务及计划任务停止证据、独立 recovery point、manifest/hash/路径预检、写入顺序、故障注入/中断处理、恢复后完整性验证和回滚步骤。未满足时保持 `RESTORE_WRITE_DISABLED`，不得绕过。
6. 秘密扫描、日志、错误、截图和文档只保存规则名、相对文件名、脱敏指纹、错误码、短哈希、耗时和摘要；绝不输出秘密值、原始资料、完整 UUID、绝对宿主路径或 Provider 原始响应。
7. 每个任务完成前必须运行适用的 `pnpm type-check`、后端/前端 build、测试、文档治理、`git diff --check`；涉及页面/运行流的任务必须浏览器验收；合入 `master` 后必须复验并推送 `origin/master`。
8. 当前未跟踪路径 `H:\ai-studybuddy\.trae-html-share-packages\` 和 `H:\ai-studybuddy\alpha-sprint-plan\` 不属于本计划；不得删除、提交、移动或用 `git clean` 处理。

## 3. Wave 设计与完成门槛

### Wave 0：正式证据基线（T02-R1、T02-R2）

**目的**：先确认真实仓库/候选包和批准 Windows 机器不存在可阻止后续工作的 P0/P1 风险。

- **T02-R1**：在受控扫描工具和候选包上执行扫描；命中只记录规则、相对路径、脱敏指纹、人工复核结论。现有 Alpha Day 0 扫描可作为输入，但要在当前正式仓库与当前候选包重新签收。
- **T02-R2**：只读采集 config/data/logs/backups/tmp/models 的 ACL、继承、主体、可写范围与 reparse 风险。若发现 P1，先创建最小修复计划和回归矩阵；没有额外批准不得写 ACL。
- **Gate**：P0=0；任何 P1 均有修复计划或已修复回归；证据不泄露隐私。未通过不得进入真实恢复写入。

### Wave 1：备份、完整性与可控恢复（T04-1～T04-3）

**目的**：把 T02G 合成预检边界扩展为可验证的正式数据保护能力。

- 自动备份只作用于明确受控输出根，白名单 payload、manifest/hash、保留策略和失败可见。
- 完整性检测覆盖全局库、学期库、备份 manifest/payload/hash，区分损坏、缺失、篡改和不可恢复。
- 真实恢复先在批准的合成数据根演练；再在明确批准的目标 Windows 机器进行恢复演练，整个过程记录停服、recovery point、预检、写入、验证、回滚和残留检查。
- **Gate**：备份不覆盖未知文件；篡改/损坏可识别；中断后可解释并回到安全状态；真实 restore 不再仅有 `-WhatIf` 预检而是有受控写入证据。

### Wave 2：复核与日志收口（T02-R3、T05-1～T05-3）

**目的**：独立复核恢复安全性，并统一运行时可审查日志。

- T02-R3 由非 T04 实现者审查真实备份/恢复的边界和证据。
- T05-1/2/3 统一后端、Adapter、脚本和渠道失败路径；定义日志等级、事件、关联短 ID 和允许字段；验证轮转、总量上限、保留/清理不会越界。
- **Gate**：不会记录秘密/学生原文/完整 UUID/绝对路径/外部原始响应；重复启动、错误和轮转均不无限增长、不误删受保护文件。

### Wave 3：学生可操作且脱敏的失败反馈（T02-R4）

**目的**：对 S1/S2/S3/S4/S5/S7 建立错误分类、API 契约、前端中文行动建议和回归矩阵。

- 覆盖输入错误、不存在、未配置、超时/下游失败和未知异常；前端不展示内部栈、路径、Provider 响应或秘密。
- S7 只验证其既定受控 MVP 边界；无合法 CLI/模型时输出已配置/待配置状态，而不是伪造成功。
- **Gate**：核心错误矩阵全绿，浏览器验收覆盖失败与重试建议；对既有成功路径无回归。

### Wave 4：T02 总体验收（T02-R6）

**目的**：关闭 T02 顶层，而非宣称整个 Phase 3 已完成。

- 汇总 T02A～T02G 与 R1～R4 的证据；确认 P0=0、P1 全部修复、真实 Windows 原生证据和完整自动化回归通过。
- 对仍剩余 P2/P3 仅记录责任、缓解、触发和排期，不能伪装为已修复。
- **Gate**：独立审查通过；`docs/04` 和风险签收一致；主线复验并推送 `origin/master` 后才将 T02 标为完成。
