## 3. 三个门禁的执行设计与成功/停止条件

### 3.1 G1：immutable model revision

**单一责任**：证明实际被加载的既有本地 FunASR 1.3.22 与 `iic/SenseVoiceSmall` 模型具备可信、不可变且可复查的 revision 身份，而非仅有名称或缓存状态。

**允许输入**：现有本地模型文件、已存 metadata/manifest、已有包元数据与安全合成样例。不得联网或下载。

**必须记录的证据**：

- 模型名称、来源、实际 immutable revision/commit hash、FunASR 版本、运行架构/平台；
- 所有实际参与验证的模型/配置/元数据文件清单及 SHA-256；
- revision 与本地 metadata/manifest 和文件哈希的对应关系；
- 许可证文本或已有许可证记录的位置与其可追溯来源；
- 任何无法验证的文件、缺失 metadata 或 hash 不一致的详细脱敏原因。

**成功标准**：每次运行都能以现有本地证据确认同一 immutable revision/commit hash，文件清单和 SHA-256 可复查且彼此一致；不会把可变引用或未验证缓存误记为 immutable。

**停止条件**：无法从现有本地证据获取可信 immutable revision；revision/manifest/hash 不一致；发现来源不可追溯。此时 `G1=BLOCKED` 或 `FAIL`（按第 6 节），不下载、不猜测、不继续把模型用于门禁关闭，并且不得自动将 T02 改为 `PASS`。

### 3.2 G2：防火墙离线隔离

**单一责任**：证明每个受试 ASR 进程在实际运行期间被临时、最小范围且可回滚的 Windows Firewall 隔离，而不是仅依赖环境变量、断网描述或 cache-only 参数。

**前置权限门槛**：执行前必须确认可为**本次 T04 试炼的具体目标进程**创建和删除临时 Windows Firewall 规则。若权限不足、无法验证规则生效范围，或无法承诺 finally 清理，立即 `G2=BLOCKED`；不得改用弱化方案，不得运行 ASR 以假装完成该门禁。

**未来操作约束**：

1. 生成带任务 ID/时间戳的临时规则名称，并在运行前记录同名规则不存在、相关规则快照、网络状态、目标可执行文件/进程、开始时间和规则的最小范围。
2. 仅为本次试炼的目标进程创建出站临时规则；不得创建永久、全局、服务级或影响其它任务的策略。
3. 在 `try/finally` 等价清理路径中删除本次临时规则；即使 ASR、超时、异常或中断也必须进入清理与记录。
4. 记录规则创建结果、运行中状态、结束后快照、删除结果和结束时间；验证同名临时规则已不存在。

**成功标准**：每次实际 ASR 运行都有可复查的规则前/中/后快照、目标进程关联和完整回滚证据；无残留规则、无系统策略改动，且没有把环境变量当作隔离替代物。

**停止/失败条件**：无权限或不可确认规则创建/回滚为 `BLOCKED`；隔离未生效、规则误伤/越界、无法删除、残留临时规则、修改永久策略或其它任务环境为 `FAIL`。任何失败均停止后续执行并优先清理。

### 3.3 G3：no-speech

**单一责任**：在已关闭 G1/G2 或其运行被明确阻断的前提下，验证既有本地模型面对静音和轻噪稳定返回结构化 `no-speech`，且绝不产生非空转写文本；同时不破坏清晰语音与中英混合语音的稳定成功。

**样例与最小重复数**：仅使用已存在的安全合成、非敏感样例：静音、轻噪、清晰合成语音、中英混合合成语音。静音与轻噪各至少运行 3 次；清晰语音和中英混合语音也须重复运行，并记录稳定性。样例都要记录生成方法、音频元数据、SHA-256 与非敏感说明。

**结构化分类**：每次结果都必须含运行 ID、样例 ID/hash、模型 revision、隔离 run ID、退出状态、耗时、资源摘要、进程清理结果以及以下之一：

- `NO_SPEECH`：静音/轻噪的结构化 no-speech，且转写字段为空；
- `TRANSCRIBED`：清晰/中英合成语音成功，结果在重复运行中稳定；
- `AUDIO_DECODE_FAILED`：损坏 WAV；
- `AUDIO_FORMAT_UNSUPPORTED`：非音频文件；
- `PROCESS_TIMEOUT`：受控超时；
- `PROCESS_CLEANUP_FAILED`、`FIREWALL_ROLLBACK_FAILED` 或其他固定失败分类。

**成功标准**：静音和轻噪各至少 3/3 稳定为 `NO_SPEECH` 且无非空转写；清晰与中英混合样例重复成功、输出稳定；损坏 WAV、非音频、超时和进程清理的既有验证仍存在并通过回归；不得靠修改 Adapter、`ConverterResult`、API 或业务代码改变分类。

**停止条件**：静音/轻噪任一次出现非空文本、无结构化 no-speech、正向样例不稳定、异常/超时无法清理，或只有修改未批准业务实现才能关闭 no-speech，均不得扩大范围。按结果将 `G3` 判为 `PARTIAL`、`BLOCKED` 或 `FAIL`，并停止把它宣称为已关闭。

## 5. 判定、回归与交付边界

### 5.1 总体判定

- **PASS**：G1、G2、G3 都有可信、可重复、可追溯证据；异常/超时/资源/进程清理回归通过；每次临时防火墙隔离均完整回滚；没有越权写入。
- **PARTIAL**：部分门禁关闭，但仍有版本、隔离、no-speech、资源、覆盖或异常处理缺口。
- **FAIL**：来源不可追溯、revision/hash 不一致、越权写入、失控或残留进程、隔离失败/未回滚、关键矩阵失败、真实数据泄露，或将可变来源伪装成 immutable。
- **BLOCKED**：没有足够本地 immutable 证据，或没有创建并回滚临时防火墙规则的权限；BLOCKED 不得被淡化为 PASS，也不得以下载、联网或环境变量替代。

即使总体为 PASS，也仅表示三个能力门禁具有当前机器上的补证；**不等于** T02 自动 PASS、ASR 已完成、S7 已完成、`AuralConverter` 可装配、生产 SLA 达标、模型可再分发，或 T05/T06 已获批准。

### 5.2 不变的 T02/T03/T04/T05/T06 边界

- T02：保留为 `PARTIAL`，直至未来执行证据被独立复核并按任务清单规则正式更新；计划本身不会升级它。
- T03：保持已入主线的 `PASS`，仅提供本机 FFmpeg 预处理能力事实。
- T04：当前仍为 `PARTIAL` 能力验证；本计划只定义如何补三个阻断门禁，不是 Adapter 装配。
- T05/T06：未启动；任何是否计划、批准、实现或评估都必须另立任务、计划、审查与用户明确批准。
