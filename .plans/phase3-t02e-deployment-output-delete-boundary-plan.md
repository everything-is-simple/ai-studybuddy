## 1. 目标与唯一范围

本切片只为未来实施建立“部署包输出受控根与递归删除安全边界”。未来获批准后，实施只可：

1. 审计并约束部署包输出目录、临时 staging 目录与允许清理目录之间的受控根关系；
2. 为将来的递归删除/清理定义可机器验证的前置拒绝条件与最小 allowlist；
3. 以仓库外、无真实数据的合成隔离夹具证明危险输入被拒绝，并证明成功清理只能发生在批准的合成目录中；

5. 使未来该边界产生的错误输出只含固定、脱敏、非绝对路径的错误码或类别。

本计划不声明当前脚本已具备上述保护，也不把规划、未来分支验证或未来主线集成表述为 T02、Phase 3 或上线完成。

## 3. 未来实施的安全契约

### 3.1 受控根关系与 allowlist

未来实现必须在任何写入、复制覆盖、压缩或删除之前，对所有候选路径做规范化并验证其关系：

- **输出根**：只能是调用方显式提供且通过校验的、由未来实施定义的受控输出根；不得隐式把仓库根、磁盘根、用户主目录、正式安装根或应用数据根当作输出根。
- **staging 根**：只能是该次操作新建的、唯一标识的受控临时子目录；它必须可证明位于批准的隔离 staging 父根之下，且不是预存目录、仓库目录或外部 worktree。
- **允许清理目录**：allowlist 必须是显式枚举、不可由任意用户输入扩展的目录类别；未来实现只可清理当前操作创建且标记为可清理的 staging 子目录，或经同等审计后明确批准的合成输出子目录。输出根本身、其父目录及任何未知目录默认不可清理。
- **路径规范化**：比较前必须取得语义一致的规范路径，并按平台适用的大小写/分隔符规则比较完整路径段；字符串前缀匹配不足以证明子目录关系。
- **越界和特殊根拒绝**：空值、空白、相对路径、无法规范化的路径、跨卷/盘符异常、`..` 逃逸、仓库根、磁盘/卷根、用户目录、正式安装根、`APP_DATA_ROOT`、正式数据、日志、备份、模型及外部 worktree 一律拒绝。
- **链接风险原则**：在枚举、复制或删除前后均需识别符号链接、junction、mount point、其他重解析点及解析后目标；默认拒绝将其作为清理目标或递归跟随。若平台能力无法可靠验证，操作必须以固定错误类别失败，不得降级为递归删除。

### 3.2 错误与证据输出契约

未来实现的所有拒绝、I/O 失败和测试诊断必须：

- 返回稳定的固定错误码或分类，例如 `DELETE_TARGET_EMPTY`、`DELETE_TARGET_OUTSIDE_ALLOWLIST`、`DELETE_TARGET_PROTECTED_ROOT`、`DELETE_TARGET_REPARSE_POINT`、`PACKAGE_OUTPUT_INVALID`；实际命名须在实施时统一确定；
- 只输出固定类别、相对逻辑名称或短标识；不得回显完整宿主绝对路径、环境变量值、目录树、原始命令输出、stack、文件内容、真实文件名或真实运行环境；
- 对成功或失败证据只记录退出状态、稳定错误码/类别、合成夹具的逻辑标签和非敏感计数；不得记录真实数据位置或内容。

### 3.3 部署包内容边界

未来静态审计和合成夹具验证必须把部署包允许内容限定为部署规范规定的编译产物、必要脚本、示例配置、兼容性元数据、manifest 与文档；至少证明下列项目不会被包含：

- `.git` 与 Git 元数据；
- `node_modules`、npm/pnpm/pip 等依赖或包管理缓存；
- 真实 `.env`/环境文件、凭据、密钥、授权码、Webhook 值；
- 正式 SQLite/应用数据、真实学生资料、真实秘密；
- 日志、`tmp`、备份、模型、运行时 venv、OCR/ASR 缓存；
- 外部 worktree 或任何未批准的宿主目录内容。

## 4. 静态审计与真实操作的严格分界

### 4.1 允许的后续验证：静态审计和合成隔离夹具

在用户批准未来实施后，允许的验证仅限：

- 对已批准候选脚本和辅助模块进行静态审计；
- 在仓库外、可再生、无真实数据的隔离父目录中创建合成输出与 staging 夹具；
- 使用无意义的合成文件名、内容与哨兵，验证路径校验、拒绝码、包内容 allowlist/exclude 规则和不跟随链接原则；
- 对经过验证的合成可清理 staging 子目录做最小化验证，并在测试结束时仅清理由测试本身创建、仍受 allowlist 约束的合成目录。

隔离夹具父目录不得位于仓库、任何 worktree、用户目录、正式安装根、`APP_DATA_ROOT`、数据、日志、备份、模型或运行时目录；测试必须预先断言隔离根与这些受保护根不相同且不互为祖先/后代。夹具不得复制或读取真实数据、环境文件或任何未批准宿主文件。

### 4.2 本轮及未获批准前明确禁止的操作

- 对正式 `APP_DATA_ROOT`、数据、日志、备份、模型、外部 worktree 或用户文件的读写/删除验证；
- 真实秘密扫描或真实部署包扫描；

## 6. 自动化测试类别与可测试拒绝条件

未来实施至少需要下列类别；所有涉及文件系统的例子均只能使用上一节定义的仓库外合成隔离夹具：

1. **规范化与包含关系单元测试**：正常受控 staging 子目录允许；空/空白、相对路径、`..` 逃逸、相邻前缀目录、跨盘/跨卷和无法规范化路径拒绝。
2. **受保护根拒绝测试**：仓库根、磁盘/卷根、用户目录、正式安装根、`APP_DATA_ROOT`、数据、日志、备份、模型、外部 worktree 与输出根自身均返回稳定拒绝类别，且没有删除调用。
3. **allowlist 与所有权测试**：未创建、预存、未知或父级目录拒绝；仅本次操作创建并带有受控标识的合成 staging 子目录可成为清理候选。
4. **符号链接/重解析点测试**：若测试平台能创建相应对象，目标本身、其子项或解析目标触及链接/重解析点即拒绝且不跟随；不能创建时，只记录平台能力限制，不能用真实目录替代验证。
5. **部署包内容静态测试**：基于合成 manifest/文件树证明 include allowlist 与排除项；测试输入不得是实际部署包、真实 `.env`、真实数据库、日志、模型或真实资料。
6. **脱敏错误输出测试**：对每个危险输入断言固定码/类别存在，并断言输出不含合成绝对路径、合成文件内容、环境值、stack、底层命令输出或哨兵。
7. **不伤害断言**：在测试前后比较仓库哨兵、受保护合成目录哨兵与隔离外哨兵，证明没有删除仓库文件、用户目录、`APP_DATA_ROOT`、正式数据、日志、备份、模型或外部 worktree 数据。

## 7. 未来通过/失败验收标准

### 7.1 通过条件

未来实施只有在以下全部满足时，才能报告为“分支实现完成，待主线集成/复验”（不是本计划阶段的状态）：

- 每次清理在操作前证明目标是规范化后的、当前操作拥有的 allowlist 合成子目录；
- 所有危险输入均在递归枚举或删除之前被拒绝，并返回脱敏固定分类；
- 测试证明链接/重解析点不被递归跟随，或在无法可靠保证时整个操作被拒绝；
- 合成部署包检查证明所有规定排除项均未包含；
- 测试证据证明仓库与全部受保护根的哨兵未被读写/删除，且不含真实数据或敏感内容；
- 用户批准范围内的针对性测试、文档治理和 `git diff --check` 均通过；实际命令、退出状态与限制如实登记。

### 7.2 失败/停止条件

发生任一情形必须拒绝操作或停止实施，不得尝试“修复后继续删除”：

- 目标为空、无法规范化、不是 allowlist 子目录、等于/包含/被包含于受保护根，或当前操作无法证明所有权；
- 解析出符号链接、junction、mount point 或其他重解析点，或无法可靠检查；
- 需要读取真实部署包、真实环境、真实数据或真实运行目录才可验证；
- 错误输出可能包含绝对路径、环境、stack、原始工具输出、文件内容或可识别真实数据；
- 发现必须扩展到备份/恢复、ACL、日志轮转/清理、防火墙、Docker/WSL、S7、G2、S3 Worker 或用户电脑验收。

## 8. 风险与回滚边界

- 本计划阶段没有文件系统实施变更，因此没有运行时回滚、部署回滚或数据恢复操作。
