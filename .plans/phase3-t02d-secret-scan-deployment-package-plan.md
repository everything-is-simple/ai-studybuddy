# PHASE3-T02D 仓库与部署包秘密扫描安全证明边界计划

**状态**：计划已创建并已完成独立审查，待用户明确批准实施。本文不是扫描器实现、真实秘密扫描结果、T02 总体完成证明或上线验收结论。

**任务**：PHASE3-T02D：仓库与部署包秘密扫描安全证明边界。

**前置事实**：PHASE3-T02 基线审计计划已经用户批准，但总体审计与全部修复仍未完成。T02A、T02B 和 T02C 已分别完成各自切片并推送 `origin/master`；T02C 的当前集成事实以主线提交 `fbea491` 为准。它们不等于 T02、Phase 3、安全审计、生产上线或用户电脑验收完成。

**本计划的作用**：将 T02 基线审计中“建立仓库/部署包 secret scan，并验证不会读取或打印命中值”的剩余 Slice 2 项，收敛为可批准、可测试、可审查的最小实现边界。当前任务只创建和审查本计划，不实现或运行扫描器。

## 1. 批准门禁与实施前提

- 计划创建和审查不构成用户对实现的批准。任何代码、测试、脚本、CI 配置或扫描执行都必须等待用户就本计划作出单独、明确的实施批准。
- 实施仅可从当时最新的干净 `master` 创建任务分支，并先重新核验任务清单、现有 T02 切片状态、工作树和受控输入边界。
- 如实现前发现真实秘密、未跟踪敏感文件、目标目录来源不明、部署包不可再生或规则会使命中原文进入终端/日志/测试失败消息，必须停止实施并仅报告脱敏的类别化风险，不得继续读取或复制内容。

## 2. 将来实施的唯一目标

建立一个本地、确定性的秘密扫描**安全证明边界**，用以证明：

1. 扫描对象只来自已跟踪的仓库文件，以及由测试在仓库外隔离目录生成的、受控、可再生且不含真实秘密的部署包夹具；
2. 扫描结果的公开和测试可观察面只含相对路径、稳定规则 ID、类别与非敏感行号或短哈希；
3. 命中值、完整配置行、原始文件内容和宿主环境不会被读取到结果模型、输出、断言、日志、异常或提交中；
4. 测试使用无效的合成哨兵，证明发现、汇总、失败与清理路径均不泄露哨兵本身。

“扫描规则/测试夹具验证”与“真实秘密扫描”必须严格区分。未来实现只验证前者；不得把任意开发机、用户目录、生产包或外部运行目录当作扫描目标，也不得把一次测试夹具扫描叙述为真实秘密扫描已经完成。

## 3. 允许范围与受控输入契约

### 3.1 已跟踪仓库输入

- 仅通过版本控制的已跟踪文件清单建立候选集；实现不得递归枚举工作区，也不得用“仓库根目录”作为隐式扫描根。
- 候选集必须排除不适合文本规则判断的文件类别，并在实现时以显式 allowlist/denylist 记录其原因；二进制或超出受控大小上限的文件应当被安全跳过且只产生类别化统计。
- 规则只能检查生成最小证明所需的受控文本片段；结果对象、错误对象和日志事件不得保留可还原命中的原文。

### 3.2 部署包测试夹具

- 仅允许测试在仓库外隔离目录创建一次性夹具；夹具文件名、内容、归档和清理目标均须由测试显式声明，且使用无效合成哨兵。
- 夹具必须可重复生成，不得从现有部署输出、应用数据、用户目录或环境文件复制内容；不得把真实部署包作为测试输入。
- 将来若需要验证打包脚本的集成点，先另建计划并获得批准；本切片不改变 package、bootstrap、check、start、health、stop、backup 或 restore 脚本。

### 3.3 明确拒绝、忽略且不得读取的对象

未来实现必须在输入发现阶段就拒绝或忽略下列对象，不打开、不解析、不计算内容哈希，且不将它们的绝对位置写入输出：

- `.env.local`、真实 `production.env` 与其他未跟踪的环境/秘密文件；
- 用户目录、`APP_DATA_ROOT`、正式运行数据、日志、备份、模型和外部 worktree 的运行数据；
- 仓库外的未知目录、真实部署包、下载缓存、系统临时目录和未受控挂载点；
- 所有不在已跟踪清单或测试明确生成清单内的文件。

拒绝信息只能使用固定错误码或类别；不得包含绝对路径、完整宿主环境、原始解析器消息、stack、配置行或命中值。

## 4. 脱敏结果与证据契约

### 4.1 唯一允许的命中字段

未来扫描结果、命令输出、测试断言和可提交证据最多可记录：

- 相对路径；
- 稳定规则 ID；
- 类别；
- 非敏感行号；
- 不能反推原文的短哈希；
- 汇总计数、固定状态和耗时桶。

短哈希只能对规则 ID、相对路径或不可逆的合成标识进行计算；不得对命中原文、完整行、完整配置对象或宿主环境整体计算并输出哈希。

### 4.2 一律禁止的字段和行为

任何实现、测试、终端输出、日志、异常、快照、文档证据或 Git 提交都不得打印、记录、断言或提交：

- 命中原文、完整 env 行、API Key、Provider URL、SMTP、Webhook 或任何真实/疑似秘密；
- `APP_DATA_ROOT` 值、绝对路径、完整宿主环境、stack 或 raw parser message；
- `process.env`、完整扫描候选内容、二进制 dump、归档内容或真实生产/用户数据；
- 为诊断方便而临时加入的 verbose、debug、失败上下文或快照输出。

测试的合成哨兵必须语义无效、只存在于受控夹具内，且断言所有可观察输出不含该哨兵。哨兵本身不得进入文档、截图、提交消息、测试名称或持久化证据。

## 5. 拟议实施切片（等待批准后执行）

1. **输入清单与拒绝边界**：确认可复现的已跟踪文件枚举方式，定义部署包测试夹具 manifest，先为未跟踪/敏感/仓库外输入写拒绝测试。
2. **纯规则与最小结果模型**：实现不保留命中文本的规则接口和结果 schema；规则以稳定 ID 和类别描述，不返回 raw match、capture group 或完整行。
3. **输出汇总边界**：实现仅消费允许字段的 formatter/CLI 或内部服务边界；任何异常使用固定摘要，禁止回显源内容和绝对路径。
4. **合成夹具证明**：在仓库外隔离目录生成无效合成哨兵夹具，覆盖单命中、多命中、跳过、拒绝、汇总和清理路径，证明 stdout、stderr、异常、日志和测试输出均无哨兵泄露。
5. **回归与人工审查**：审查 diff、结果 schema、日志调用点、测试失败输出和运行命令，确认未触及部署脚本或其他 T02 剩余范围；仅在批准范围内运行目标测试和要求的通用验证。

每一切片均需先以测试表达“不读取/不泄露”契约，再加入最小实现；任一步不能证明输入或输出安全时停止，不以扩大扫描范围来补救。

## 6. 未来测试与验收标准

实施获批后，至少应有自动化测试证明：

- 已跟踪候选清单之外的路径不会被读取；对拒绝目标的测试通过监控或受控 seam 证明没有内容访问；
- 仓库外夹具只能由测试 manifest 生成，且不包含真实秘密或真实配置复制品；
- 每个命中结果只含第 4.1 节允许字段；序列化、日志、stdout、stderr、异常和测试报告均不含合成哨兵；
- 相对路径保持相对、可重复，拒绝和错误信息不含绝对路径、环境值、stack 或 raw parser message；
- 扫描规则/夹具验证不触发 Provider、SMTP、Webhook、OCR、whisper.cpp 或任何网络服务；
- 失败路径也不泄露合成哨兵，测试不会因 assertion message、snapshot 或调试输出重新暴露它；
- 仅修改批准范围内的文件，并通过文档治理、`git diff --check` 及批准时定义的针对性测试。

验收记录只写命令退出状态、通过数量、稳定规则 ID/类别、相对路径或短哈希和脱敏摘要；不得记录真实扫描目标或命中内容。
