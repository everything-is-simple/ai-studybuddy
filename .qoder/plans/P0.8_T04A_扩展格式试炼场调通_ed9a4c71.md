- [ ] **Step 3: 实现 `fetchReadableUrl(input, options = {})`。**

每一个初始/重定向 URL 必须按顺序执行全部规则：

1. `new URL` 后仅允许 `http:`/`https:`；拒绝 user-info、空 hostname、`localhost`、`.localhost`。
2. 用 `node:net.isIP` 检查字面 IP；拒绝 IPv4 `0/8`、`10/8`、`100.64/10`、`127/8`、`169.254/16`、`172.16/12`、`192.168/16`、`198.18/15`、`224/4`，以及 IPv6 `::`、`::1`、`fc00::/7`、`fe80::/10` 和 IPv4-mapped 私网/回环地址。错误固定为“不允许访问本机、私网、回环或链路本地地址”。
3. 域名使用 `dns.promises.lookup(hostname, { all: true, verbatim: true })`；无地址、任一解析地址非公网、DNS 失败均拒绝。不能只解析 IPv4。
4. `undici.fetch` 使用 `redirect: "manual"`、`AbortSignal.timeout(10_000)`；仅处理 3 次 `301/302/303/307/308`，第 4 次返回“重定向次数超过 3 次，请手动复制正文”。
5. **必须**使用 `undici` 的 `fetch` 和 `Agent`（`import { fetch, Agent } from "undici"`），并把为当前请求建立的受限 `Agent` 作为 `dispatcher` 传给该 `fetch`。不依赖 Node 内置全局 `fetch`：虽然某些 Node/undici 组合可经全局 dispatcher 共享配置，但跨版本与已安装 `undici` 的兼容性不应作为安全边界。用 `undici.Agent` 的自定义 `lookup` 在每次连接时重新解析和校验公网地址。若此模式无法稳定支持，记录 blocker；不得降级为任何跳过连接时复验的 `fetch` 调用。
6. `Content-Length` 超过 `5 * 1024 * 1024` 立即拒绝；缺失或不可信时使用 `response.body.getReader()` 流式累计，超限 `reader.cancel()`。错误为“网页内容超过 5 MB 限制，请手动复制正文”。
7. 404 返回“页面不存在（HTTP 404）”；其他 HTTP 失败返回“网页请求失败（HTTP <status>），请手动复制正文”；超时、DNS/TLS/network、验证码、反爬和空正文均返回包含“抓取失败，请手动复制正文”的中文提示。
8. 非 `text/html` 写 warning，但可在限额内尝试；若内容类型为 `application/pdf` 或其他非 HTML 格式，warning 应明确说明"该链接指向的不是网页（Content-Type: <实际类型>），请直接下载后上传文件"。成功 metadata 至少含 `finalUrl`、`status`、`contentType`、`redirectCount`、`byteCount`、`charCount`。不记录 Cookie、Authorization 或原始 HTML。

不使用代理、Cookie 模拟、无头浏览器、反爬绕过、无限重试或页面 JS 执行。百度百科、知乎等失败时只给人工复制出口。
