## 任务 1：设计 StorageAdapter 接口与 storage_key 约定

### 1.1 新增文件

`packages/backend/src/adapters/storage.ts`

### 1.2 接口草案

```typescript
export interface PutFileInput {
  semesterId: string;
  courseId?: string;          // 可选，归属课程
  originalName: string;       // 原始文件名，仅用于推断扩展名
  data: Buffer | Readable;    // 支持 Buffer / Stream
}

export interface PutFileResult {
  storageKey: string;         // 逻辑 key，如 semesters/<id>/files/<course>/<uuid>.ext
  size: number;
}

export interface GetFileResult {
  stream: Readable;
  size: number;
  lastModified: Date;
}

// 注：T03 不持久化 contentType；download 路由通过扩展名推断（pdf/jpg/png/txt/md）

export class StorageAdapter {
  async put(input: PutFileInput): Promise<PutFileResult>;
  async get(storageKey: string): Promise<GetFileResult>; // 不存在则抛 StorageKeyNotFound
  async delete(storageKey: string): Promise<void>;       // 不存在则抛 StorageKeyNotFound
  exists(storageKey: string): boolean;
  // 仅用于测试/诊断
  resolvePath(storageKey: string): string;
}
```

### 1.3 storage_key 规则

- 格式：`semesters/<semester-id>/files/<course-id>/<uuid>.<ext>` 或 `semesters/<semester-id>/files/common/<uuid>.ext`
- 仅保存相对路径，不保存绝对路径
- 所有操作最终通过 `resolveAppDataPath()` 解析，拒绝 `..` 和越界

### 1.4 依赖

- 如需要处理 multipart 上传，新增 `multer` 到 `packages/backend/package.json`
- 也可以先接受 `application/octet-stream` raw body，T07 接入 materials 时再补 multipart

**决策（默认）**：使用 `multer` 处理 `multipart/form-data`，并设置单文件大小上限（默认 50MB），避免大文件撑爆进程内存或填满磁盘。

```typescript
const upload = multer({
  storage: multer.memoryStorage(),
  limits: { fileSize: 50 * 1024 * 1024 },
});
```

## 任务 2：扩展路径安全模块

修改：`packages/backend/src/db/paths.ts`

新增：

```typescript
export function getSemesterCourseFilesDir(semesterId: string, courseId: string): string;
export function getSemesterCommonFilesDir(semesterId: string): string;
export function resolveStorageKeyToPath(storageKey: string): string;
```

- `resolveStorageKeyToPath` 的实现步骤：
  1. 先 `path.normalize(storageKey)`，消除 `..`、`\\` 等可折叠片段
  2. 再按 `/` / `\\` 分段，检测是否存在 `..`
  3. 最后调用 `resolveAppDataPath()`，并校验最终 resolved 路径仍在 `APP_DATA_ROOT` 内
- 所有路径必须在 `APP_DATA_ROOT` 内；否则抛出 `STORAGE_PATH_ESCAPE`

## 任务 3：实现 StorageAdapter

在 `packages/backend/src/adapters/storage.ts` 中实现：

1. `put(input)`
   - 生成 UUID 文件名
   - 根据 `courseId` 选择目录：`files/<courseId>/` 或 `files/common/`
   - 确保父目录存在
   - 写入文件（Buffer 直接写；Stream 用 `pipeline`）
   - 返回 `storageKey` 与 `size`

2. `get(storageKey)`
   - 解析路径
   - `fs.existsSync` 不存在抛 `STORAGE_KEY_NOT_FOUND`
   - 返回 `fs.createReadStream()` 与 stat

3. `delete(storageKey)`
   - 解析路径
   - 不存在抛 `STORAGE_KEY_NOT_FOUND`
   - `fs.unlinkSync`

4. `exists(storageKey)`
   - 解析路径并返回 `fs.existsSync`

5. 异常类型
   - `StoragePathEscapeError`
   - `StorageKeyNotFoundError`

## 任务 5：吸纳 GPT 反馈——读操作不隐式建库

### 5.1 问题定位

`packages/backend/src/db/connection.ts` 中：

```typescript
export function openDbAtPath(dbPath: string): DatabaseType {
  fs.mkdirSync(path.dirname(dbPath), { recursive: true }); // 会创建父目录
  const db = new Database(dbPath);                         // 会创建空库
  ...
}
```

`backups.ts::checkDatabaseIntegrityAtPath` 与 `dev.ts::db-health` 的读路径如果传入不存在的数据库，可能创建空库/目录。

### 5.2 修复方案

新增只读/存在性打开接口：

```typescript
export function openExistingDbAtPath(dbPath: string): DatabaseType {
  if (!fs.existsSync(dbPath)) {
    throw new Error(`DB_NOT_FOUND ${dbPath}`);
  }
  const db = new Database(dbPath, { fileMustExist: true });
  db.pragma("journal_mode = WAL");
  db.pragma("foreign_keys = ON");
  return db;
}
```

- `openDbAtPath` 保持原样，用于初始化/写入路径
- 健康检查、完整性检查改用 `openExistingDbAtPath`

### 5.3 影响点

- `packages/backend/src/db/backups.ts`（**注意：该文件在 `85b06af` 中已存在，本次为修改而非新增**）
  - `checkDatabaseIntegrityAtPath` 调用前先做存在性判断，或改用 `openExistingDbAtPath`
- `packages/backend/src/api/dev.ts`
  - `db-health` 当前实现已先判断 `fs.existsSync(globalDbPath)`，可继续保留，但学期库健康检查也改用 `openExistingDbAtPath`
