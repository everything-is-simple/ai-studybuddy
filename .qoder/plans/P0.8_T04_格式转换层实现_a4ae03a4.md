# P0.8 T04 格式转换层实现计划

## 目标

在 `I:\ai-studybuddy` 主仓库实现共同底座格式转换层，支持：

- `PdfConverter`：将 PDF（文本层）转换为纯文本
- `OcrConverter`：将图片（JPG/PNG）通过 RapidOCR Python 子进程转换为纯文本
- `TextConverter`：将 Markdown/纯文本原样返回

所有 Converter 统一返回 `@ai-studybuddy/shared` 已定义的 `ConverterResult`：

```typescript
interface ConverterResult {
  ok: boolean;
  sourceType: "pdf" | "image" | "text";
  text?: string;
  metadata?: { pageCount?: number; charCount?: number; hasFormula?: boolean; hasTable?: boolean };
  warnings?: string[];
  error?: string;
}
```

## 范围与边界

- 只实现 Converter 本身，**不**实现 S2 资料上传完整流程（T07 再做）
- 只实现**直接文本提取**路径，**不**实现分级 fallback（PDF.js 渲染 / PaddleOCR / 视觉 Provider / 人工校正等后续再做）
- Converter 不直接读写 SQLite，只接收 `Buffer` 或文件路径，返回结构化结果
- 不引入 BullMQ / Redis / Docker，OCR 子进程同步调用即可（后续 Worker 层会异步化）
- 扫描版 PDF 当前先按 OCR 路径处理（由调用方判断 sourceType）

## 接口设计

### 1. `PdfConverter`

```typescript
export class PdfConverter {
  async convert(input: Buffer | string): Promise<ConverterResult>;
}
```

- `input` 为 PDF 文件 Buffer 或本地绝对路径字符串
- 使用 `pdf-parse` 解析 PDF Buffer
- 输出 `sourceType: "pdf"`
- `metadata.pageCount` 为 PDF 页数
- `metadata.charCount` 为文本字符数
- `metadata.hasFormula` / `metadata.hasTable` 本阶段不检测，固定返回 `undefined`
- 当 `text.trim() === ""` 时返回 `ok: false`，`error` 提示"未能提取到文本，可能是扫描版 PDF，建议走 OCR 路径"；否则即使中文字符数为 0 也返回 `ok: true`，仅在 `warnings[]` 中提示"未检测到中文字符，请确认内容语言或来源"

### 2. `OcrConverter`

```typescript
export interface OcrConverterOptions {
  pythonPath?: string; // 默认 "python"
  timeoutMs?: number;    // 默认 60000
}

export class OcrConverter {
  constructor(options?: OcrConverterOptions);
  async convert(input: Buffer | string): Promise<ConverterResult>;
}
```

- `input` 为图片文件 Buffer 或本地绝对路径字符串
- 内部将 Buffer 临时写入 `tmp/` 目录后，调用 Python Worker
- 调用 `packages/backend/src/scripts/ocr-worker.py <imagePath>`
- Python 脚本使用 `rapidocr_onnxruntime` 识别图片，stdout 输出 JSON
- Node 端通过 `spawn` / `execFile` 调用，设置超时和编码
- 输出 `sourceType: "image"`
- `metadata.charCount` 为识别字符数
- `metadata.hasFormula` / `metadata.hasTable` 本阶段不检测，固定返回 `undefined`
- 失败时返回 `ok: false`，记录 stderr 摘要
- **Python 脚本路径解析**：在 `converter.ts` 中通过 `path.resolve(__dirname, "../scripts/ocr-worker.py")` 获取；build 后 `dist/adapters/converter.js` 的 `__dirname` 会指向 `dist/adapters`，因此 `../scripts/ocr-worker.py` 对应 `dist/scripts/ocr-worker.py`。需要在 build 步骤中将 `src/scripts/ocr-worker.py` 复制到 `dist/scripts/ocr-worker.py`，本阶段通过 `package.json` 的 build 脚本追加复制命令实现，或改用 `node -e` 在启动时复制；不采用硬编码 `src/` 路径。

### 3. `TextConverter`

```typescript
export class TextConverter {
  async convert(input: Buffer | string): Promise<ConverterResult>;
}
```

- `input` 为文本文件 Buffer 或本地绝对路径字符串
- 直接按 UTF-8 解码
- 输出 `sourceType: "text"`
- `metadata.charCount` 为文本字符数
- `metadata.hasFormula` / `metadata.hasTable` 本阶段不检测，固定返回 `undefined`
- 若解码失败，返回 `ok: false`

## Python OCR Worker 脚本

`packages/backend/src/scripts/ocr-worker.py`：

- 接收命令行参数 `<imagePath>`
- 使用 `rapidocr_onnxruntime.RapidOCR()` 识别
- stdout 输出 JSON：

```json
{
  "ok": true,
  "text": "...",
  "lines": [{"text": "...", "confidence": 0.95}],
  "charCount": 120,
  "elapsedMs": 1234
}
```

- 异常时输出：

```json
{ "ok": false, "error": "..." }
```

- OCR Python 脚本路径在 build 后需要从 `dist` 正确解析，避免硬编码 `src/` 路径
